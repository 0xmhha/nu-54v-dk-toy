# Practice upgrade fixture

`Fixture.swift` writes a synthetic supported v2 personal profile to the iOS Keychain service `nu54.personal.profile.v2` using the isolated bundle ID in `Info.plist`. It contains no real key or wallet. Build it as an iOS simulator app with Xcode ad-hoc signing, install and launch it, and verify its logged `fixture keychain status 0` before installing the current app signed the same way with `PRODUCT_BUNDLE_IDENTIFIER=com.nu54renter.w02upgrade`. Run `PracticeUpgradeSmoke/testSupportedPreviousProfileOpensAfterUpgrade` on the same simulator. Do not use a real application bundle ID or real profile. This tests a supported pre-practice data shape, not a previously shipped binary.

# W03 signed installation picker fixture

`install_fixture_server.py` generates temporary, non-executable MCUboot and P10 Ed25519 keys/images and calls the production board-release CLI. It listens only on `127.0.0.1:18941`; its `observed` report is synthetic and is never proof of a real board. Set `W03_FIXTURE_DIR` to the Documents directory of a **separate disposable iOS file-sharing fixture app** on the selected simulator, then run the server. It writes `setup.json`, `trust.json`, a disabled `.txt`, and an oversized `.json`; receipt endpoints create `wrong.json` and `receipt.json` for the challenge requested by the UI test. Never point it at a real customer app container.

Install the candidate P02 simulator app with isolated bundle identifier `com.nu54renter.w02practice`. Run the XCTest `SceneSmoke/SetupReceiptSmoke` on the same simulator while the fixture server is running. It uses the system document picker, checks oversized-file rejection, selects the two independent test documents, confirms the comparison, relaunches with the same challenge, rejects a different-device signed receipt and accepts the matching receipt. Confirm that the result bundle contains **one passed test**; a successful command with zero tests is not evidence. The isolated app and fixture both use synthetic state only. The currently supported fixture provider app has `UIFileSharingEnabled` and `LSSupportsOpeningDocumentsInPlace` enabled; its `Documents` directory is created through `simctl get_app_container` for the disposable `com.nu54renter.filefixture` bundle. The actual P01 board and physical observation are outside this test.
