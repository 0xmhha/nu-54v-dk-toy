# NU-54V DK 제품 방향 재선정

2026-09-14 · 제품 선택 전 비교안. 기존 Air Cue 기획은 사용자 피드백에 따라 철회했다.

## 이번에 고를 기준

완성 후 주 3회 이상 사용할 만한 구체적인 장면, 손으로 만지는 하드웨어의 이점, 12주 안에 끝낼 수 있는 범위가 우선이다. LLM은 텍스트 처리·의도 해석·대화에 쓰고, 단순 볼륨 조절이나 게임 입력에까지 끼워 넣지 않는다. 저렴한 완제품을 복제할 때는 실제 비용 차이가 있는지부터 확인한다.

사용자가 제시한 [BC250 게임기 영상](https://www.youtube.com/watch?v=4vl7Q6Ii7Vo)은 브라우저에서 제목·제작자 설명·챕터를 확인했다. 설명에는 직접 설계한 3D 프린트 케이스, 냉각 구조, 주변기기 시험, Bazzite 설치 및 Steam 실행이 나온다. 전체 영상을 시청해 성능을 검증한 것은 아니다. 이 사례에서 가져올 방향은 부품을 조립한 뒤 일상에서 쓸 수 있는 결과물까지 완성하는 것이다.

NU-54V DK는 nRF54L15 기반 MCU 보드다. 게임이나 일반 대화형 LLM은 PC에서 실행하고, 이 보드는 센서·입력·표시·무선 통신을 맡는 구조를 제안한다. nRF54L15의 128MHz Cortex-M33, 256KB RAM 및 BLE·PDM·I²C 등의 사양을 바탕으로 한 설계 판단이다. [Nordic 사양](https://docs.nordicsemi.com/r/bundle/ps_nrf54l15/page/keyfeatures_html5.html)

## 후보 비교

|---|---|---|---|---|---|

| 게임·영상용 모션 리모컨 | 소파에서 포인터·영상 조작, PC 게임 한 종류에 기울기 입력 | IMU의 회전·기울기, 버튼, 진동, BLE | 선택 기능: 사용자 요청을 정해진 동작으로 해석 | 4만~8만원 | 중상 |

난이도는 주 5~7시간, 한 종류의 PC 운영체제로 범위를 제한했을 때의 기획 판단이다. 외형 소형화와 배터리 수명은 측정 전 보장하지 않는다.

## 1. AI 작업 다이얼 — 현재 우선 추천

### 쓰는 모습

마우스로 문장을 선택하고 복사한다. 책상 위 다이얼로 ‘번역 / 요약 / 다시 쓰기’를 고른 뒤 버튼을 누른다. PC의 작은 도우미가 클립보드 내용을 LLM에 전달하고 미리보기를 보여준다. 다이얼로 결과를 고르고 버튼으로 클립보드에 확정한다. 붙여넣기는 처음에는 사용자가 한다. 기존 문서를 모델 응답으로 자동 덮어쓰지 않는다.

평소에는 같은 다이얼로 볼륨·재생·스크롤을 조작한다. 길게 누르는 별도 동작은 PC 마이크 녹음으로 연결하고, 말한 내용을 메모 초안으로 변환한다. 1차 버전의 음성은 **기기 내 마이크가 아니라 PC 마이크**를 사용한다. 내장 마이크는 후속 확장이다.

### 직접 만드는 이유

키보드 단축키를 외우는 대신 손에 익는 다이얼과 버튼으로 자주 쓰는 동작을 묶는다. LLM 제공자, 프롬프트, 결과 형식을 직접 교체할 수 있다. 다만 단축키 몇 개로 충분한 사용자라면 별도 하드웨어의 이점이 작다. 첫 주에 실제 자주 할 동작 세 개를 정해야 한다.

### 참고 제품과 만들 범위

[Stream Deck Neo](https://www.elgato.com/ww/en/p/stream-deck-neo-black)의 물리 단축키와 [SmartKnob](https://github.com/scottbez1/smartknob)의 회전 인터랙션을 참고한다. 개별 LCD 키나 상용 플러그인 생태계 전체를 복제하는 계획은 아니다.

필수 부품은 NU-54V DK, 자기식 회전 각도 센서와 자석 또는 초기 로터리 엔코더, 작은 OLED, 버튼 3개, 케이스다. 센서 데이터는 BLE로 PC 도우미에 보내고, PC에서 화면 표시용 상태를 되돌려준다. 초기 USB는 전원용이다.

SmartKnob 원본은 ESP32·BLDC 모터 기반이라 펌웨어를 그대로 사용할 수 없다. 12주 필수 목표는 모터 없는 다이얼이다. 가변 저항감·가상 클릭을 내는 모터 제어는 후속 버전 또는 별도 제어 모듈을 쓰는 확장 과제로 남긴다.

### 12주 도착점

| 기간 | 결과 |
|---|---|
| 1~2주 | 쓸 동작 3개 선정, 보드·SDK 확인, 센서 입력과 BLE 수신 |
| 3~4주 | 다이얼·버튼·화면으로 메뉴를 고르고 실행하는 기본 동작 |
| 5~6주 | PC 도우미와 LLM 연결, 복사한 텍스트 처리·미리보기·결과 확정 |
| 7~8주 | PC 마이크 기반 누르고 말하기, 재연결·오류·취소 처리 |
| 9~10주 | 케이스 제작, 일주일 사용 후 불편한 동작 수정 |
| 11~12주 | 실사용 검증, 조립·설치 가이드와 전시 시연 |

최종 시연은 ‘문장 선택·복사 → 다이얼 조작 → LLM 결과 → 결과 복사’와 ‘평상시 미디어 조작’을 보여준다. 평가는 정확하지 않은 모델 답변을 감추지 않고 동작 성공률과 사용자 조작 횟수로 한다. 모델 요청 지연과 기기의 입력 지연을 따로 잰다.

## 2. AI 메모 기기 — LLM의 쓰임이 가장 분명한 후보

버튼을 누르고 ‘다음 프로젝트에서 확인할 것’을 말하면 나중에 PC에서 제목·핵심 내용·할 일로 정리된다. 목적은 본인의 짧은 아이디어 기록이다. [Plaud NotePin의 녹음→전사→정리 흐름](https://au.plaud.ai/blogs/articles/transcribe-audio-to-text-plaud-notepin)을 참고하되, 자신이 고른 로컬 모델 또는 API와 Markdown 저장을 사용한다.

NU-54V DK에는 마이크가 필요하고 녹음 버퍼만으로 장시간 저장할 수 없다. 16kHz·16bit·모노 PCM은 초당 32,000바이트, 1분에 약 1.92MB다. 256KB RAM 전부를 오디오에 써도 8초 정도이므로, **외부 저장장치에 짧은 메모를 저장한 뒤 BLE로 PC에 전송**하는 구성이 필요하다. 즉시 BLE 스트리밍은 성능 실험 후 별도로 판단한다. [Nordic PDM 설명](https://academy.nordicsemi.com/courses/nrf54l-series-express-course/lessons/lesson-3-peripherals-and-system-components/topic/communication-peripherals/)

12주 범위는 최대 60초 단위 개인 메모, 녹음 시작·완료 피드백, 외부 저장, 파일 재전송, PC 음성 인식·LLM 정리, Markdown 저장이다. 스마트폰 백그라운드 동기화·긴 회의·화자 분리는 제외한다. 처음부터 작은 펜던트 크기를 약속하지 않고 DK가 들어가는 휴대 녹음기 크기로 만든다.

핵심 실패 가능성은 음질, 저장 중 전원 손실, BLE 전송 복구, 실제로 휴대할 크기다. 상용 녹음기와 동등한 녹음 품질·앱 완성도·사용료 절감을 보장하지 않는다.

Medium 제목 후보: **「버튼 하나로 생각을 노트로: 내 모델과 연결하는 AI 메모 기기 제작기」**.

## 3. 게임·영상용 모션 리모컨 — 재미를 우선한다면

손목으로 포인터를 움직이고 버튼으로 재생·볼륨·선택을 조작한다. 별도 모드에서는 기울기를 PC 게임 한 종류의 조작으로 연결한다. Steam을 실행하는 장치는 기존 PC이며, NU-54V DK는 무선 입력장치다.

IMU와 버튼을 읽어 BLE HID 마우스·키보드 입력으로 보내는 경로를 먼저 검증한다. [Nordic HIDS mouse 예제](https://nrfconnectdocs.nordicsemi.com/ncs/latest/nrf/samples/bluetooth/peripheral_hids_mouse/README.html)는 nRF54L15 DK를 지원하지만 NU-54V DK의 배선·보드 설정은 별도로 맞춰야 한다.

12주 목표는 PC 한 운영체제, 영상 조작, 게임 한 개다. 모든 게임에서 Xbox 패드로 인식되거나 TV에 직접 연결된다고 가정하지 않는다. LLM은 자연어로 동작을 고르는 선택 기능으로 둘 수 있지만 핵심은 지연·드리프트·손맛이다. 여기서는 LLM을 빼도 좋은 제품이 될 수 있다.

## 4. 무선 3D 작업 컨트롤러 — CAD를 자주 쓴다면

노브를 밀고 당기고 비틀어 모델 시점을 조작한다. [Hall 센서를 활용한 DIY CAD Mouse](https://github.com/ChromeBee/Hall-Effect-Sensor-CAD-Mouse-Spacemouse)처럼 비싼 전용 입력장치의 일부 사용 경험을 직접 만드는 방향이다.

주요 과제는 센서 조합과 기구의 복원력, 축 간 간섭, 보정이다. 기존 USB 펌웨어를 NU-54V DK에 그대로 올릴 수 없으며, BLE→PC 도우미→Blender 경로를 별도로 만든다. 첫 지원 앱은 Blender 하나로 한정한다. 센서 수가 ADC 채널 수를 넘으면 외부 ADC·멀티플렉서가 필요하다. LLM의 필요성은 낮다.

## 5. AI 책상 로봇 — 만들고 보여주는 재미가 가장 큰 후보

화면에 눈이 있는 작은 고정형 로봇이다. 개발 작업이 끝나면 얼굴과 몸짓으로 알려주고, 머리를 터치하면 미리 정한 질문이나 짧은 대화가 시작된다. PC가 작업 상태·LLM·음성 처리를 맡고 NU-54V DK는 터치·움직임 감지, 표정, 서보를 담당한다.

12주에는 바퀴 없는 몸체, 서보 1~2개, 터치 반응, PC 작업 이벤트 한 종류, 짧은 대화만 만든다. 음성 입출력은 먼저 PC 마이크·스피커를 재사용한다. 모터 전원은 보드의 GPIO로 공급하지 않고 별도 전원 경로로 설계한다. 표현이 재미있어도 알림을 과하게 만들면 사용성이 떨어지므로 반응 빈도를 조절한다.

작업 종료 이벤트는 PC 도우미가 명시적으로 전달한 프로세스 종료·빌드 결과 등이다. 어떤 앱의 내부 작업 상태든 자동으로 읽을 수 있다고 가정하지 않는다.

## 다음 결정

현재 추천은 실용성과 완성 가능성을 함께 보는 **AI 작업 다이얼**이다. LLM 자체가 가장 큰 가치를 만들어야 한다면 **AI 메모 기기**, 조립·움직임·게임의 재미가 우선이면 **모션 리모컨 또는 책상 로봇**이 맞다.

사용자가 마음에 드는 제품을 고른 다음 그 제품으로 1주차 Medium 원고와 예상 이미지를 새로 만든다. NU-54V DK 공식 보드 이미지는 재사용할 수 있다. 기존 Air Cue 원고·이미지는 이전 방향의 기록이며 새 제품의 산출물로 제시하지 않는다.
