# 첫 결제 시연 — 통합 작업과 완료 기준

> 2026-09-18 범위 갱신: [12주 완료 범위 v3](twelve-week-completion-scope-v3.md)가 최신 기준이다. 아래 기존 검토에서 패스키·녹음·스마트 계정 등을 후보/후속으로 둔 부분은 새 범위를 따른다. 초기 EOA 개발 순서와 고객 가스 부담은 유지하며, 새 Cloud Wallet의 MPC는 별도로 설계한다.

작성: 2026-09-17. 인터뷰 중간 산출물이며 최종 Seed나 구현 완료 보고서가 아니다. 네 저장소 검토를 바탕으로 개발할 작업을 나눴다. 아래 세부 범위·일정은 제안이며, 사용자가 미정 정책까지 승인한 것으로 보지 않는다.

후속 사용자 결정: 결제 네트워크 수수료는 **고객 부담으로 먼저 구현하고, 운영자 후원은 이후 추가**한다. 아래 개발 순서에 반영했다. 후속 답변으로 StableNet RPC와 네이티브 토큰 가스 지불도 확정했다. 체인 ID 8283을 조회했다. 계정 방식은 초기 일반 지갑(EOA), 후속 스마트 계정으로 확정했다. [네트워크 확인](stablenet-testnet-baseline.md)

## 1. 먼저 연결할 한 가지 흐름

초기 온체인 경로는 `NU 기기가 EOA 거래 승인·서명 → 키오스크/연결 서비스가 서명 거래 중계 → StableNet RPC → Indexer·영수증 검증`이다. 서명 중계자는 고객 키를 받지 않으며, 전송 nonce·가스 견적·재시도와 실제 승인 내용을 맞춘다. 스마트 계정과 운영자 후원은 후속 단계이므로 해당 코드의 호환성 차이가 첫 EOA 시연을 막는 선행조건은 아니다.

**대여 기기 설정 → 카페 주문 → 기기에서 금액 확인·승인 → 더미 토큰 지급 → 입금 검증 → 매출·영수증·패스포트 반영 → 잔액 회수·반납**을 첫 통합 시연으로 제안한다.

기존 키 가져오기와 신규 생성은 모두 유지한다. 매장 직접 수취, React Native 태블릿 앱, 고객/사장님 모바일 앱, 운영 백오피스, 컨트랙트, 기존 Indexer도 유지한다. 첫 정상 결제를 먼저 연결하는 것이 나머지 확정 요구사항의 삭제를 뜻하지 않는다. 근접 검증·보호 영역 서명·암호화 import의 실제 장비 시험은 개발 단계에서 진행한다.

## 2. 새로 확인한 API 연결 차이

검토 기준: poc-platform `fcad7900de5ceea5e3ef586774609ad00739b760`, indexer-go `5baff647f3cfab935f73db1bbd742ad42317045f`. 실제 엔드포인트를 호출한 결과가 아니라 해당 커밋의 클라이언트와 서버 코드를 비교한 결과다.

| 항목 | 현재 SDK | 현재 Indexer | 제안 조치 |
|---|---|---|---|
| ERC-20 주소별 RPC 요청 | `[address, isFrom, limit, offset]` 배열 | `{address, isFrom, limit, offset}` 객체를 decode | RPC 요청 어댑터 또는 검증된 GraphQL 조회로 통일 |
| 같은 RPC 응답 | 전송 배열을 직접 기대 | `{transfers, total}` 반환 | 응답 wrapper를 풀고 최소 단위 금액·timestamp 타입 정규화 |
| 주소별 거래 GraphQL | Transaction에 `gasUsed`, `timestamp`, `status` 요청 | `receipt.gasUsed`, `receipt.status`, `blockTimestamp` 제공 | 조회 필드 및 UI 변환 수정. receipt 미관측은 성공으로 추정하지 않음 |

근거: [SDK 전송 요청](https://github.com/0xmhha/poc-platform/blob/fcad7900de5ceea5e3ef586774609ad00739b760/packages/sdk-ts/core/src/clients/indexerClient.ts#L347), [서버 RPC 요청·응답](https://github.com/0xmhha/indexer-go/blob/5baff647f3cfab935f73db1bbd742ad42317045f/pkg/api/jsonrpc/methods_address.go#L312), [SDK 거래 query](https://github.com/0xmhha/poc-platform/blob/fcad7900de5ceea5e3ef586774609ad00739b760/packages/sdk-ts/core/src/clients/indexerClient.ts#L411), [서버 Transaction 타입](https://github.com/0xmhha/indexer-go/blob/5baff647f3cfab935f73db1bbd742ad42317045f/pkg/api/graphql/types.go#L318).

앞서 확인한 Paymaster 데이터/해시 차이도 남아 있다. 이 때문에 ‘기존 기능 재사용’을 ‘설정값만 바꾸면 완료’로 계산하지 않는다. 수정 대상으로 제안한 조회 문서는 [indexer-read-contract.graphql](integration/indexer-read-contract.graphql)에 있다. 실행 검증 전 초안이다.

## 4. 완료를 판정할 대표 시나리오

| 상황 | 기대 결과 |
|---|---|
| 정상 구매 | 주문 1건, 지급 1건, 매출 1회, 영수증 1건, 적립 1회가 연결됨 |
| 잘못된 토큰/금액/수취 주소 | 정상 결제로 확정되지 않고 차이 내역에 표시됨 |
| 승인 전 거리 이탈/취소 | 해당 승인 요청 중단. 새 세션에서는 다시 확인 |
| 서명·제출 뒤 BLE 끊김/앱 재시작 | 기존 시도 추적. 단순 연결 해제를 온체인 취소로 표시하지 않음 |
| 이벤트 중복·Indexer 지연·재연결 | 누락 범위 재조회와 중복 제거. 지연을 실패로 단정하지 않음 |
| 체인 관측 되돌림 | 확정 정책에 따라 영향받는 지급 재검토; 매출/혜택 보정 이력 유지 |
| 취소 뒤 늦은 지급/중복 지급 | 새 정상 매출을 임의 생성하지 않고 예외로 분류 |
| 반납 후 환불 | 반환된 기기 주소로 자동 지급하지 않고 검증한 환불 수취 주소 사용 |
| 다른 매장 계정/운영자 | 허용 범위 밖 거래·고객 기록·키에 접근하지 못함 |
| AA 번들 일부 실패 | 번들 영수증 성공만으로 모든 주문을 결제 완료 처리하지 않음 |

테스트용 시드·주소·금액으로 수행하며, 결과를 실제 하드웨어/실제 서비스 검증과 구분해 남긴다. 실자산 운영의 법률·운영 적용 검토는 별도 결정 상태를 유지한다.

## 5. 12주 배치 제안

| 기간 | 우선 결과물 |
|---|---|
| 1~2주 | 버전/조회 호환 조합, 테스트 자산, 주문 API 골격. 개발 착수 후 보드 서명·근접·import 위험 항목 시험 병행 |
| 3~4주 | 고객 부담 지급과 주문 대사 연결, RN 주문/지갑 화면 골격. EOA 거래 서명·가스 추정·nonce 처리 연결 |
| 5~6주 | NU 실제 승인·서명과 키오스크 결제 연결; 제출 뒤 단절 복구 |
| 7~8주 | 사장님 매출·수취 화면, 운영 백오피스, 영수증·패스포트 |
| 9~10주 | 환불·대여·반납, 중복/지연/권한/오입금 시나리오 |
| 11~12주 | 통합 회귀 시험, 협력 카페 환경 시연, 제작 기록·사용 가이드 |

인력·기존 서비스 가동 상태·개발 숙련도는 아직 확인되지 않았다. 이는 의존성을 보여주는 초안이며 12주 내 전체 완료 보장이 아니다. 음성 녹음·AI 정리·범용 패스키는 요구 후보로 유지하며 첫 결제 흐름의 개발 여유와 별도 검증 결과에 따라 범위를 정한다.

## 6. 지금 결정할 내용과 계속 진행 가능한 작업

사용자가 **초기 고객 부담 → 후속 운영자 후원** 순서를 확정했다. 후원 기능과 그 버전 문제는 첫 고객 부담 결제의 필수 선행조건에서 분리한다. 후속 답변에서 StableNet 네이티브 토큰 가스 지불을 선택했다. USDC 수수료 청구용 Paymaster는 초기 필수가 아니다. 초기는 일반 지갑(EOA)이며 스마트 계정은 이후 적용한다. 첫 결제의 필수 구성에서 Kernel·EntryPoint·Bundler·Paymaster를 제외하고, 기존 SDK의 일반 거래·조회 코드와 NU signer를 연결한다.

고객이 준비할 자산은 구매용 USDC/더미 토큰과 가스용 StableNet 네이티브 토큰이다. 네이티브 토큰 확보 경로와 충전 지원은 별도 설계한다. 앱 견적에는 구매대금과 수수료 추정/상한을 구분하고, 잔액 부족 시 부족한 자산을 표시한다. 실패한 전송에도 발생할 수 있는 비용과 실제 수수료를 구매대금과 따로 기록한다. 후원 한도·시점·환불 수수료 정책은 별도 결정이다.

| 남은 결정 | 막는 작업 | 답변 전 진행 가능 |
|---|---|---|
| 선택 체인의 배포 주소·확정 정책 | 실제 토큰 배포·결제 완료 판정 | RPC/체인 ID는 확인. API 수정·데이터 모델·로컬 시험 준비 |
| 네이티브 가스 확보·충전 지원 | 고객 온보딩·잔액 부족 안내 | 네이티브 잔액 조회·수수료 분리 표시 설계 |
| 후속 스마트 계정 전환 방식 | 자산 이동·주소 유지 여부·권한 전환·복구 | 초기 EOA 결제는 독립적으로 개발 |
| 환불 승인/수수료/부분 환불 | 실제 환불 실행 | 환불 상태·원거래 연결·한도 검증 설계 |
| 12주 실자산 파일럿 필수 여부 | 최종 출시 완료 기준 | 더미 토큰 통합 시연 준비 |

미정 값은 [integration-baseline.json](integration/integration-baseline.json)에 null로 남긴다. 검토한 커밋은 배포 승인 버전이나 최신 호환 버전이라는 뜻이 아니다.
