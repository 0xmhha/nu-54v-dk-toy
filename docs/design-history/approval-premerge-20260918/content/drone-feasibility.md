# NU-54V DK 드론 활용 가능성과 SCOUT-01 제안

2026-09-14 · 문헌 기반 기획 검토. 실제 보드·조종기·드론의 동작을 검증한 결과가 아니다.

## 결론

드론 프로젝트에 사용할 수 있다. 다만 개발보드 자체가 비행 제어기·모터 드라이버·관성 센서를 모두 갖춘 완성 드론 보드는 아니다. 12주 안에 조립하고 날려보는 제품을 목표로 한다면 **NU-54V DK 기반 자작 조종기 + 검증된 비행 제어기와 호환 통신 경로를 가진 기체 + 경량 맞춤 외장**을 우선 추천한다.

## 세 가지 사용 방식

| 방식 | NU-54V DK의 역할 | 추가로 필요한 것 | 12주 적합성에 대한 판단 |
|---|---|---|---|
| 자작 조종기 | 스틱·버튼·IMU 입력, 표시, BLE 송신 | PC의 명령 변환 프로그램, 기체 SDK 또는 호환 송신기, 비행 제어기가 있는 드론 | 가장 우선 추천. PC 시뮬레이터 입력부터 확인 가능 |
| 기체의 보조 보드 | LED·추가 센서·상태 표시·명령 전달 | 별도 비행 제어기, 전원부, 양쪽 통신 연결, 탑재 중량 여유 | 가능하지만 DK의 크기·무게·소비전류를 먼저 측정해야 함 |
| 주 비행 제어기 | 센서 수집, 자세 추정, 제어 루프, 모터 출력 모두 담당 | IMU, 모터·ESC/드라이버, 전원 설계, 제어 소프트웨어, 기구·진동 대책 | 임베디드·제어 경험이 필요한 큰 과제. 12주 자유 비행 완성을 보장하기 어려움 |

nRF54L15의 Cortex-M33, SPI/I²C, PWM 등은 센서와 제어 인터페이스를 만드는 기반이 된다. 그러나 주변장치가 있다는 사실은 특정 비행 펌웨어가 바로 실행되거나 자세 제어의 주기·지연이 검증되었다는 뜻은 아니다. NU-54V DK용으로 바로 사용할 검증된 비행 펌웨어 조합은 이번 조사에서 확인하지 못했다. [Nordic 데이터시트](https://docs.nordicsemi.com/r/bundle/ps_nrf54l15/page/keyfeatures_html5.html)

실제 소형 드론에도 역할 분리의 사례가 있다. Crazyflie는 STM32F4가 비행 제어를 맡고 nRF51822가 무선 통신·전원 관리를 담당한다. 이것은 NU-54V DK가 해당 기체에 그대로 호환된다는 뜻이 아니라 구조의 참고 사례다. [Bitcraze 플랫폼 설명](https://www.bitcraze.io/documentation/system/platform/)

## SCOUT-01: 가상 비행을 연습하고 실물로 이어지는 SF 탐사 드론

자작 조종기를 먼저 PC의 BLE HID 컨트롤러로 연결해 비행 시뮬레이터에서 쓴다. 다음 단계에서 지원되는 드론 플랫폼을 정하고 그 기체의 SDK·무선 경로로 조작 명령을 전달한다. 기체에는 가벼운 탐사 로봇 모양의 캐노피와 작은 LED를 달고, 착륙 패드나 통과 게이트를 만들어 수동 조종 놀이를 한다.

구상 경로는 다음과 같다.

`스틱·버튼 → NU-54V DK → BLE → PC의 명령 변환 프로그램 → 기체가 지원하는 통신 경로 → 비행 제어기 → ESC/모터`

PC 시뮬레이터용 HID 입력과 실제 드론의 비행 명령 프로토콜은 다르다. Steam에서 조이스틱으로 인식되더라도 그 상태로 아무 드론에 연결해 조종할 수 있는 것은 아니다. BLE 신호만으로 모든 상용 드론을 제어하거나 영상까지 전송한다고 가정하지 않는다.

실제 비행의 빠른 자세 제어는 기체 안에서 수행해야 한다. BLE·PC·LLM 응답을 기다리며 모터를 안정화하는 구조로 만들지 않는다. 통신 손실·오래된 명령·저전압 대응은 기체가 지원하는 방식으로 설정하고 확인해야 한다. 갑자기 모터를 끄는 것을 모든 상황에 적합한 통신 손실 대책으로 취급하지 않는다.

## 센서와 전원

자세 안정화에는 가속도·각속도를 읽는 IMU와 제어 소프트웨어가 필요하다. 고도 유지·위치 유지·자율 이동까지 요구하면 필요한 센서와 추정 기능도 늘어난다. 예를 들어 PX4는 자신의 지원 기능에 필요한 센서 구성을 별도로 명시한다. 그 구성을 모든 단순 수동 드론의 최소 부품 목록으로 일반화하지 않는다. [PX4 센서 문서](https://docs.px4.io/main/en/sensor/index)

모터는 NU-54V DK의 GPIO나 보드 전원 핀에서 직접 구동하지 않는다. 모터 종류에 맞는 ESC 또는 드라이버와 배터리·전원부가 필요하다. 어떤 출력 신호를 사용할 수 있는지는 실제 비행 제어기·ESC 조합으로 확인한다.

3D 프린트 외장은 질량·무게중심·프로펠러 간섭·냉각을 확인해야 한다. 1차 범위는 검증된 프레임에 경량 캐노피와 마운트를 추가하는 정도로 잡는다. 보호 가드도 출력했다고 곧바로 충돌 안전성이 검증되는 것은 아니다. DK 전체를 초소형 기체에 실을 수 있을지는 중량과 추진 여유 확인 전에는 미정이다.

## LLM은 어디에 쓰는가

기본 제안은 비행 전에 사용자의 조종 연습 목표를 정리하거나, 사전에 정의한 코스의 임무 설명을 만들고, 비행 후 실제 로그로 일지를 작성하는 것이다. 자연어로 임의의 실내 자율 비행 경로를 만들거나 모터를 직접 제어하는 기능은 12주 범위에 넣지 않는다.

예: ‘오늘은 세 번의 부드러운 착륙을 연습한다’ → 고정 코스 안내 → 사용자가 조종 → 수집 가능한 기록과 사용자의 소감으로 비행 일지 생성. 위치·착륙 횟수 등의 데이터가 없으면 LLM이 그 사실을 만들어내게 하지 않는다.

## 12주 마일스톤 제안

| 기간 | 목표 |
|---|---|
| 1~2주 | 보드와 스틱 입력, BLE 연결, 대상 시뮬레이터에서 조종 확인 |
| 3~4주 | 조종기 외장, 입력 보정, 기체 플랫폼·통신 경로 선정 및 부품 수급 |
| 5~6주 | 기체 조립, 프로펠러를 제거한 상태의 명령·상태·통신 손실 처리 검증 |
| 7~8주 | 선정 기체의 공식 절차에 따른 통제된 공간에서의 단계적 수동 비행 시험 |
| 9~10주 | 경량 외장과 LED, 중량·간섭 확인 및 재시험, 연습 코스 제작 |
| 11~12주 | 실제 수집 로그·임무 설명, 사용성 검증, 제작 가이드·시연 |

기체 예산, 실내/실외, 조종 경험, 보드 탑재 여부가 정해지기 전에는 부품 가격과 비행시간을 약속하지 않는다. 선택한 플랫폼에 맞춰 일정을 조정한다. NU-54V DK 자체로 비행 제어를 만드는 길을 택한다면 위 일정 대신 제어 실험·시험대 검증 중심으로 다시 짜야 한다.

## 이미지의 해석

`assets/concepts/scout-01.png`는 기체와 조종기의 외형 콘셉트다. 조종기의 화면 수치는 예시이고, 이미지에 PC 중계 경로는 생략되어 있다. 네 개의 가드·로터와 SF 캐노피의 배치는 구조·추력·비행 성능을 검증한 도면이 아니다. 이미지상의 공중 정지·자율 비행 기능은 제안하지 않았다.
