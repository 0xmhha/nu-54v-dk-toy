## 2. 글 구성 결정

1주차는 메이커 **구성 A: 제품 기획서형**을 채택한다. 제품의 용도와 만들 범위가 있어 멘토에게 구현상의 빈칸을 설명하기 좋다. 이후 주차는 구성 B의 목표·실험·관찰·다음 확인사항 흐름으로 기술 로그를 쓴다. 마지막 회고는 첫 글의 목표와 실제 결과를 비교한다.

## 3. 프로젝트 범위

**가치 가설:** 사용자가 정한 조건을 일정 시간 넘었을 때 눈에 보이는 신호를 주면 환기를 떠올리는 데 도움이 될 것이다. 버튼 기록과 실제 사용 관찰로 검증한다. 집중력 향상이나 건강 개선을 성과로 주장하지 않는다.

**12주 필수 결과:** NU-54V DK를 넣은 탁상 시제품 1대, SCD41 CO₂·온습도 읽기, 숫자와 상태 표시, 버튼 이벤트, BLE 전송, PC CSV 기록, 통풍 케이스, 24시간 동작 기록, 재현 문서.

**확장 과제:** 배터리·저전력 최적화, e-paper, 전용 앱, 장기 기기 내 저장, 모델 기반 패턴 분석. 이 항목은 기본 기능이 검증된 후에만 시작한다. Wi-Fi 및 클라우드는 기본 구성에 넣지 않는다.

USB는 전원 공급과 보드가 제공하는 디버그·시리얼 경로로 사용한다. nRF54L15 자체의 네이티브 USB 데이터 기능을 전제하지 않는다.

## 5. 기술 구성과 초기에 검증할 가정

데이터 경로: SCD41 → I²C → NU-54V DK의 수집·상태 처리 → OLED / 상태 LED / BLE → 연결된 PC의 CSV 파일. 버튼 이벤트는 다음 BLE 데이터와 함께 보낸다. 기기의 기본 동작은 PC 연결과 무관하게 유지한다.

- **SDK·보드 지원:** Zephyr 보드 지원 [PR #117771](https://github.com/zephyrproject-rtos/zephyr/pull/117771)은 확인 당시 Open. 그 PR의 타깃은 `nucode_nu54/nrf54l15/cpuapp`이며 내장 DAPLink와 외장 J-Link 경로가 기술되어 있다. 설치된 nRF Connect SDK의 지원이나 사용자 보드 리비전과 일치한다고 단정하지 않는다. 제조사 예제와 지원 브랜치를 확인하고 작동하는 버전·커밋·보드 리비전을 기록한다.
- **센서 드라이버:** [Zephyr SCD41 바인딩](https://docs.zephyrproject.org/latest/build/dts/api/bindings/sensor/sensirion,scd41.html)에 드라이버와 측정 모드가 안내되어 있다. 선택한 SDK에 실제로 포함되어 있는지 확인한다.
- **전원:** SCD41 단품은 3.3V에서 주기 측정 시 평균 약 15mA, 최대 피크 205mA로 명시된다. 보드 레귤레이터와 커넥터 공급 능력을 확인한다. 별도 전원 사용 시 공통 접지, 풀업 및 신호 레벨, 역급전 방지를 함께 설계한다. 센서를 5V로 공급할 때 I²C를 무조건 직결하지 않는다. [데이터시트 §2.1](https://sensirion.com/media/documents/48C4B7FB/67FE0194/CD_DS_SCD4x_Datasheet_D1.pdf)
- **배선:** I²C 핀 번호는 회로도와 실물 확인 후 확정한다. 외형이 비슷한 다른 DK의 핀 번호를 대입하지 않는다. 브레이크아웃의 레벨 시프터·풀업 여부도 확인한다.
- **수집:** 정상 주기 측정의 5초 간격으로 시작한다. 연속 3회 읽기 실패나 마지막 정상값 이후 20초 경과 시 오류 상태로 전환하는 것이 제안 규칙이다.
- **알림 규칙 초안:** 1,000ppm 이상이 120초 지속되면 주의 표시, 900ppm 이하가 120초 유지되면 해제한다. 나머지 구간은 직전 상태를 유지한다. 초기·센서 오류 상태는 별도로 표시한다. 이 숫자는 제품 실험용 가정이며 공인 기준이나 검증된 최적값이 아니다.
- **기록:** `sequence, uptime_ms, co2_ppm, temperature_c, rh_pct, state, vent_event`를 전송하고 PC가 수신 시각을 추가한다. PC 미연결 구간은 공백으로 남긴다. 기기에서 장기간 이력을 보관·복구하는 기능은 범위 밖이다.
- **검교정·기구:** 자동 보정의 사용 조건, 센서 온도 오프셋, 열원과의 거리, 공기 흐름을 확인한다. 교정 기준이 없는 야외값을 임의로 고정해 강제 보정하지 않는다. 케이스 전후의 경향 비교는 할 수 있지만 기준 계측기 없이 절대 정확도를 검증했다고 쓰지 않는다. [설계 가이드](https://sensirion.com/media/documents/0D0C9129/623B1183/Sensirion_CO2_Sensors_SCD4x_design-in_guide.pdf)

위 규칙과 수치는 아직 구현·측정하지 않은 목표다.

주차는 원문 스터디 일정에 대응한다. 오늘부터 새로 12주를 세어 11월 25일과 모순되는 날짜를 만들지 않는다. 1주차 작업이 늦어진 만큼 환경 확인과 부품 수급은 즉시 병행한다.

| 연결 | 강제 연결 해제 10회 후 수신기 재연결 시 10회 모두 수집 재개 | 회차·재개까지의 시간 기록. 미연결 구간 자동 복구는 요구하지 않음 |
| 실제 사용 | 환기 전후 관찰 3회 이상, 버튼 시각 기록 | 위치·시간·창문 상태·로그를 함께 남김. 항상 농도가 낮아진다고 미리 결론 내리지 않음 |
| 시연 | 부팅→측정→알림→버튼→BLE 기록을 설명 가능 | 현장 실측과 별도 녹화·기록 준비. 가상 입력 사용 시 명시 |
| 재현성 | 부품표·리비전·배선·소프트웨어 버전·실행법 공개 가능 | 문서만 보고 빌드·연결 절차를 다시 수행 |

## 8. 일정이 밀릴 때의 조정

2주차까지 보드 다운로드가 안 되면 제조사·멘토에게 리비전, SDK, 디버거 조합을 묻는다. NU-54V DK 사용 목표를 유지하고 외형 설계를 뒤로 보낸다. 4주차까지 센서 값이 안정적이지 않으면 BLE보다 전원·배선·드라이버 문제를 먼저 해결한다. 8주차에 기록 도구가 늦어지면 전용 UI를 만들지 않고 검증용 BLE 도구와 작은 PC 수집 프로그램으로 끝낸다. 케이스 일정이 밀리면 통풍 가능한 범용 케이스를 사용한다.
