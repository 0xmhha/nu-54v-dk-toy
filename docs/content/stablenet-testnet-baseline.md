# StableNet 시연 네트워크와 가스 정책

> 2026-09-18 범위 갱신: [12주 완료 범위 v3](twelve-week-completion-scope-v3.md)가 최신 기준이다. 아래 기존 검토에서 패스키·녹음·스마트 계정 등을 후보/후속으로 둔 부분은 새 범위를 따른다. 초기 EOA 개발 순서와 고객 가스 부담은 유지하며, 새 Cloud Wallet의 MPC는 별도로 설계한다.

확인일: 2026-09-17. 사용자가 이번 제품에 사용할 체인과 공개 URL을 지정했다. 조회 전용 JSON-RPC 요청과 공개 탐색기 HTML을 확인했다. 배포·송금·서명 요청은 하지 않았다.

## 1. 확정 및 관측 결과

| 항목 | 값 | 근거 |
|---|---|---|
| 네트워크 | 사용자가 지정한 StableNet 테스트 체인 | 사용자 결정 |
| RPC | `https://api.test.stablenet.network/` | 사용자 제공, HTTP 200 JSON-RPC 응답 확인 |
| 체인 ID | `8283` / `0x205b` | `eth_chainId`와 `net_version` 응답 |
| 탐색기 | `https://explorer.stablenet.network/` | 사용자 제공, HTTP 200 공개 HTML 확인 |
| 표시 통화 | `WKRC` | 탐색기 HTML 표기와 기존 SDK 네이티브 통화 설정 |
| 통화 소수점 | 18자리 설정 | 기존 SDK 설정 근거. RPC가 반환한 네이티브 토큰 메타데이터는 아님 |
| 결제 자산 | 시연용 더미 토큰, 실제 서비스 USDC 우선 | 기존 사용자 결정. 주소는 아직 미정 |
| 초기 가스비 | 고객이 StableNet 네이티브 토큰으로 부담 | 사용자 답변 반영 |
| 운영자 후원 | 이후 단계에서 추가 | 기존 사용자 결정 |

조회한 RPC 메서드는 `eth_chainId`, `net_version`, `eth_blockNumber`, `web3_clientVersion`, `eth_gasPrice`다. RPC 응답 원문은 [조회 기록](integration/stablenet-rpc-observation.json)에 저장했다. 관측 시점의 블록 높이와 가스 가격을 고정 운영값으로 사용하지 않는다.

근거: [사용자 지정 RPC](https://api.test.stablenet.network/), [탐색기](https://explorer.stablenet.network/), [SDK 네이티브 통화 설정](https://github.com/0xmhha/poc-platform/blob/fcad7900de5ceea5e3ef586774609ad00739b760/packages/config/src/networks.ts#L44).

## 2. 앱과 기기에서 다룰 잔액

- 결제대금: 고객의 USDC/시연용 더미 토큰 잔액에서 매장으로 지급한다.
- 네트워크 수수료: 고객의 네이티브 잔액에서 납부한다. 같은 이름의 ERC-20 wrapped 토큰 잔액으로 대체 판단하지 않는다.
- 앱에는 두 잔액과 각각의 부족 금액을 구분해 표시한다. 구매대금, 예상 가스비와 승인 상한, 처리 후 실제 수수료를 구분한다.
- 반납 전에는 결제 토큰 회수에 필요한 가스를 남겨두고, 토큰 회수 뒤 남은 네이티브 잔액 처리로 이어지는 순서를 설계한다. 완전한 잔액 0이나 무료 회수를 보장하지 않는다.
- 가스 토큰의 확보 경로·충전 지원과 환불 가스비 부담은 아직 미정이다. 테스트 토큰 발행만으로 네이티브 가스가 생기는 것으로 취급하지 않는다.

사용자는 초기 일반 지갑(EOA), 후속 스마트 계정 적용을 확정했다. 첫 시연은 고객 EOA의 토큰 전송과 네이티브 가스 납부로 구성하며, Bundler·Paymaster는 필수 경로에 두지 않는다.

## 3. 환경 설정에서 주의할 차이

기존 SDK에는 8283이 `Local` 이름으로 기록되어 있고 탐색기 저장소에는 별도 8284 테스트넷 프리셋도 있다. 이번 프로젝트는 그 이름을 추측해 선택하지 않고 **사용자가 지정한 RPC + 실제 응답 체인 ID 8283**을 기준으로 설정한다. 동일 체인 ID라도 다른 네트워크의 배포 주소나 인덱싱 데이터를 섞지 않도록 배포환경 식별자와 배포 코드도 함께 확인한다.

사용자 지정 탐색기 URL은 기록했지만, 해당 화면의 백엔드가 이 RPC와 같은 블록 해시를 제공하는지까지 대조하지는 않았다. Indexer·Bundler·Paymaster API 주소 역시 탐색기 URL로부터 추정하지 않는다. 네 저장소의 검토 커밋이 현재 서비스의 배포 커밋이라는 뜻도 아니다.

남은 검증: 실제 Indexer API와 관측 체인 일치, 토큰 주소·ABI·권한, 확정 정책, SDK 서명/가스 추정과 체인 호환성. 보드 실기 검증은 기존 결정대로 개발 단계에서 수행한다.
