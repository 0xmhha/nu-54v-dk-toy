# 시연 경로 화면 일치 점검

화면 인수는 지금까지 상태와 흐름을 기준으로 했다. 이 문서는 시연에 보이는 여섯 페이지에서 [화면 설계서](book.html)의 모양과 실제 지갑 앱(`products/p02-user-app`)이 어디서 다른지 적고, 무엇을 고쳤는지 기록한다. 판정은 설계서의 상태 문구·표시 데이터·동작 배치와 앱 소스, 실기 화면 요소 트리를 대조한 결과다. 개인 지갑 화면은 Android가 캡처를 막아 픽셀 비교는 하지 않았다.

## 공통 골격

| 항목 | 설계서 | 앱 (이번 변경 전) | 이번 변경 |
|---|---|---|---|
| 머리 | `NU Wallet` 표식과 보드 연결 칩 | 화면 제목만 | `Brand` 머리와 보드 연결·미등록 칩 |
| 하단 탐색 | 지갑·결제·둘러보기·설정 탭 | 없음, 홈의 버튼으로 이동 | 등록을 마친 개인 지갑 홈에 탭 추가 |
| 색과 글자 | `book.css` 토큰(잉크·진녹·민트·크림) | 버튼 색 하나와 회색 계열 | `src/ui/theme.ts`로 토큰 이식 |
| 동작의 위계 | 주 동작 하나, 보조, 목록 행 | 같은 모양의 버튼만 | 주(채움)·보조(외곽선)·목록 행 3종 |
| 입력란 | 안내문이 읽히는 입력란 | 안내문 대비 부족 | 안내문 색을 보조 글자색으로 지정 |

## 확인하지 않은 것

- 바뀐 화면을 실기나 시뮬레이터에서 픽셀로 보지 않았다. 시험(469건)과 화면 요소 구조로만 확인했다.
- W09–W11이 있는 `src/merchant/CustomerOrders.tsx`와 W12의 `WalletMaintenance.tsx`는 아직 새 부품을 쓰지 않는다.

## 앱 구조 재구성 후 에뮬레이터 점검 (2026-11-23)

지갑 앱을 하단 탭 네 개(지갑·결제·둘러보기·설정) 구조로 바꾼 뒤 Android 에뮬레이터(Pixel 3a, API 34)에서 처음 실행 상태부터 점검했다. 에뮬레이터에는 블루투스가 없어 실제 보드 연결 단계는 확인하지 않았다.

| 흐름 | 결과 |
|---|---|
| 첫 실행 | 체험 카드, 지갑 선택, 하단 탭이 보인다 |
| 새 보드 설치 | 세 단계 안내와 주 버튼 하나. 설치 중에는 탭을 숨기고 Back은 지갑 선택으로 돌아간다 |
| 체험 시작(대여) | 공통 색·글꼴로 바뀌었다. Back은 지갑 선택으로 돌아간다 |
| 둘러보기 → 여행·시장 | Back은 둘러보기로 돌아간다 |
| 둘러보기 → 근처 매장, 결제 탭 | Back은 지갑 탭으로 돌아간다 |
| 설정 하위 화면 | 화면 제목이 하위 화면 이름으로 바뀌고 Back은 설정으로 돌아간다 |
| 시스템 다크 모드 | 앱은 밝은 테마로 유지되고 입력란 안내문이 읽힌다 |

독립 감사(impeccable audit 기준) 점수는 재구성 첫 단계 뒤 9/20, 수정 뒤 13/20이었다.

### 남은 문제

- 체험 화면은 방문자에게 "SW3을 길게 눌러 페어링 모드"를 안내한다. 그런데 설치를 마친 상용 보드에서 SW3 길게 누르기는 페어링이 아니라 복구 창을 연다(`products/p01-device-firmware/app/src/main.c`의 SW3 처리, `device_pilot_active()`). 방문자 체험에 쓸 보드 구성과 연결 방법을 정해야 한다.
- 여행·시장 화면은 아직 공통 부품을 쓰지 않는다.
- 결제 탭의 등록 입력란은 iOS 장면 시험이 바로 입력하므로 첫 화면에 남아 있다.
- 다크 테마는 남은 화면을 색 토큰으로 옮긴 뒤에 켠다.
