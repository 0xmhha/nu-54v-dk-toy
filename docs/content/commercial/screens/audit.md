# 페이지 UX와 제품 설계 교차 감사

개인 하드월렛, 대여·클라우드 지갑, 가맹점 거래, 여행과 선택형 시장, 운영자·개발자 화면을 실제 사용 주체별로 대조했다. 보드 버튼이나 체인 확정처럼 화면 외부에서만 일어나는 결과도 연결 대상으로 포함했다. 검토 기준은 [제품별 PRD·IA·유즈케이스](../products/README.md), [지갑·모바일 설계](../wallet-and-mobile.md), [공유 프로토콜](../protocol.md), [가맹점 지급·정산 설계](../merchant-payments.md)다.

## 검증 방법과 한계

- 각 페이지는 역할·진입·완료 기준과 연결된 PRD/UC를 갖는다. 작성 데이터에서 정적 HTML과 영역별 Markdown을 생성한다. 검사기는 모든 원문 ID의 연결, 깨진 전이, 검토 도구로만 열 수 있는 고립 상태, 원본과 생성물의 일치 여부를 확인한다.
- 문서 원본은 저장소의 주소·해시 축약 규칙을 따른다. 체인 원본과 분리한 합성 EVM 식별자를 화면에서만 펼쳐 전체 주소 비교와 테스트 수신 QR을 검토한다.
- 주문·회차·환불 및 운영 업무에는 별도 전이 검사를 두었다. 보드 승인·체인 확정·조회 전환 커밋이 사용자 버튼으로 바뀌거나, 예시 주문과 금액·수령 주소가 달라지면 검사에 실패한다. 테스트 수신 주소 QR의 표기와 XRPL 공유 카드의 주소·태그·네트워크도 대조한다. [전이 검사](check_journeys.py)
- Chromium에서 페이지 검색·직접 주소·브라우저 뒤로 가기·새로고침과 버튼/외부 사건 전환을 확인했다. 1280px, 390px, 320px에서 200% 글자 확대까지 구분해 제목, 터치 표적, 가로 넘침, 스크립트 오류를 검사했다. 폼 입력과 계정·가격·주문은 고정 예시다.
- 출시 인수에는 실물 보드·OS 페어링, 신뢰 표시 수단, 화면 읽기 보조기 실제 음성/포커스, 독립 복원, 네트워크 장애, 결제 부하와 잔액 대사, 초보자·고령자 사용성 시험이 남아 있다. 각 페이지의 완료 기준과 해당 제품 UC에서 결과 증거를 수집한다.

**최종 실행 결과** — Chromium 세 배치에서 각각 86페이지·461상태를 검사해 화면 제목·행동/사건 링크·가로 넘침·터치 표적·스크립트 검사 오류 0건이었다. 문서에서 화면으로 가는 경로 1,977개와 네 종류 수신 QR의 모듈 패턴을 검산했다. 기준 커밋에 설계 변경을 적용한 격리 사본의 `make docs-check`는 동결 기준, 마스킹 규칙, 자체 검사 34개, 문서 링크 5,337개 검사를 통과했다.

저장소 루트에서 다음 명령으로 원문과 화면집을 다시 대조할 수 있다. 화면 데이터나 인수 문구를 편집한 경우 첫 명령의 `--check`를 생략해 생성물을 갱신한다.

```sh
python3 docs/content/commercial/screens/build_book.py --check
python3 docs/content/commercial/screens/check_journeys.py
```
