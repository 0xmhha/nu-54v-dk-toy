## 진입 구조와 접근 권한

P02의 둘러보기·결제 탭에 나타나는 사용자 정보와 백엔드 소유자를 함께 정한다. 위치·음성 동의 요청은 해당 기능을 처음 선택할 때 제시한다.

| 상위 → 하위 | 보이는 정보와 가능한 조작 | 접근 조건과 오류 시 이동 |
|---|---|---|
| 탐색 → 지도/목록 → 장소 | 맛집·명소·지역·필터·영업/갱신 시각 | 비로그인 탐색 허용 설계, 위치 거절 시 지역 입력 |
| 장소 → 시간/메뉴 → 예약·디파짓/선주문 | 금액·취소조건·픽업 지점·잔금 | 주문 전 본인 세션, 결제 후 결제 탭의 동일 예약으로 |
| 내 여행 → 발자취/후기/챌린지/추천 코스 | 방문 근거·공개 범위·스탬프·추천 입력 | 목적별 동의, 미동의 기능은 안내 후 탐색으로 |
| 개인정보 → 녹음/전사/동의/삭제 요청 | 보유기간·제공자·처리 상태·열람 | 본인만 조회, 제공자 지연은 대기 상태 유지 |

## 정보 객체와 관계

장소와 가맹점·지점을 연결하되 한 장소가 결제 가맹점이 아닐 수 있다. 예약 ID는 P05 소유, P09는 참조만 보관한다. 후기에는 최소 자격 근거, 여행 기록에는 소유자·동의 버전·삭제 작업 ID를 연결한다.

## 상태와 복귀 위치

장소 탐색 → 재고 확인 → 예약 대기 → 디파짓 확인 → 예약 확정/조건 충족 → 잔금/픽업/취소. 여행 기록은 동의 없음 → 동의됨 → 철회/삭제 대기 → 삭제 완료의 독립 상태를 갖는다.

## 화면별 복귀와 검토

장소 상세에서 좌석 예약과 좌석 없는 픽업을 구분한다. 예약 조건에는 총액, 이번 예약금, 별도 잔금, 취소 조건을 함께 표시하고 각 지급은 기기 승인과 결과 조회를 따로 거친다. 지급 결과가 불명확하면 기존 예약을 재조회하며 새 결제를 만들지 않는다. 픽업 번호는 지급 확정과 이행 접수 후 표시하며 준비 완료와 구분한다. 취소 접수와 별도 환불 지급의 대기·확정도 원주문에서 분리한다.

여행 홈의 **내 여행**은 공개 진입점이다. 허브를 열거나 **탐색**으로 돌아갈 때 개인 서비스 자격이나 기기 권한을 요청하지 않고 검색 지역과 지도를 유지한다. **예약**을 누르면 현재 등록된 고객·지점의 P05 예약 상세를 열고 지급 영수증을 재조회한다. 개인 목적지를 누른 뒤에만 등록된 P09 프로필과 해당 목적의 기록을 읽는다. 각 목적지의 뒤로 가기는 허브로 복귀한다. [T10 진입과 데이터 조회](../../../../../scripts/ios/scene-smoke/fixtures/t10-travel.md)

내 여행에서 후기 자격·스탬프, 목적별 기록 동의·삭제, AI 코스와 챌린지를 각각 연다. 테스트 후기는 실제 지급과 이용 근거가 필요한 실구매 배지와 구분하고, 보상은 원장 확정 전까지 대기로 표시한다. 삭제 상태에는 기기·서버·제공자 및 원본·전사·파생물·대기열을 표시한다. 추천 후보는 영업·이동·예산과 출처를 검토하고 일정 충돌 시 비교 후 선택 적용한다.
