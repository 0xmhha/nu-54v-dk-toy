## 진입 구조와 접근 권한

계약 자체의 정보구조는 호출자·읽기 뷰·쓰기 권한·이벤트로 정의한다. 가맹점이 보는 화면은 P05, 고객 영수증은 P02/P04가 제공한다.

| 상위 → 하위 | 보이는 정보와 가능한 조작 | 접근 조건과 오류 시 이동 |
|---|---|---|
| 배포 → 네트워크/버전/ABI | 체인 ID·계약·허용 토큰·기준 블록 | 공개 읽기, 신뢰 manifest 검증 실패 시 중단 |
| 등록부 → 가맹점/주소 버전 | 효력 시작·변경·철회와 지급 가능 여부 | 승인된 등록자, 권한 없는 수정 거절 |
| 정산 → 지급 호출/주문 소비/증거 | 도메인·만료·실제 이전·이벤트 | 서명 검증, 실패 원인과 해시 제공 |
| 환불·기존 적립 → 환불/구버전 인출 | 원금·환불 누계·잔여 인출 가능액 | 환불 재원·역할과 v1 점주의 인출 권한 분리 |

## 정보 객체와 관계

논리 주문은 P05에서 한 계약 버전에 귀속한다. 온체인 순서는 체인·계약·트랜잭션·로그 위치로 식별한다. 지급과 환불은 원주문으로 연결하고 가스 비용을 별도 집계한다.

## 상태와 복귀 위치

미사용 → 실행 중 → 지급됨 또는 revert로 미사용 유지. 한 시도의 revert는 다른 유효 시도를 막지 않는다. 지급 후 환불은 별도 상태·이벤트이며 과거 지급 기록을 삭제하지 않는다.

## 배포 검증 담당자 화면

신뢰 manifest를 선택한 뒤 체인, 토큰, ABI, 계약, 등록부 버전과 기준 블록을 표시한다. 도메인 불일치는 제출 보류 및 배포 검증 재진입으로 연결한다. 성공 증거는 주문 소비·실제 수취 순증·로그 위치·확정 증거를 함께 표시하고, revert는 해당 시도의 원복과 별도 가스 비용을 표시한다. v1 적립금·cashOut·대여 잔액 조회는 계약 버전을 고정하고 기존 조회 참조를 유지한다.
