## 제공 순서와 책임

의도→계약 검증→직접 이체→잔액 차이 확인→이벤트를 단일 실행으로 고정한다. 고객 이행은 P05가 확정 증거를 받은 뒤에 진행한다.

| 단계 · 책임 | 선행 조건과 작업 | 다음 단계로 넘어갈 증거 |
|---|---|---|
| 계약 담당 · 명세와 자금 | P05와 버전·nonce·환불 권한, 8283 데모의 별도 v2 테스트 예치와 가맹점 가스 재원 확인 | 구/신 원장, 자금 출처, 허용 토큰 표 |
| 계약·QA · 이체 | 정상·거절·거짓 성공·재시도·권한 철회를 계약 시험에 포함 | 수취인 순증, revert 상태, 부분 환불 경합 벡터 |
| 릴리스 · 소비자 전환 | P10 ABI 생성 → P07 인덱싱 → P05 주문 발급 버전 연결 | 배포 manifest·바이트코드·이벤트 대조와 v1 인출 회귀 |

## 전환과 장애 대응

새 주문만 활성 v2로 발급한다. 기존 서명 주문은 원 도메인에서 만료·확정을 대사한다. 장애 시 신규 발급을 일시 중지하고 이미 발급한 메시지의 유효성을 추적한다. 이전 버전 자금은 별도 승인·이동 증거가 필요하다.

## 결정이 필요한 항목

| 정산 프로필 | 지급 원천 | 트랜잭션 제출과 가스 비용 |
|---|---|---|
| 8283 가맹점 데모 · 고정 | 신규 v2 계약의 전용 테스트 예치금 | 가맹점 측에서 제출하고 네트워크 비용을 낸다. 구계약 예치금과 분리한다. |
| 상용 개인 EVM 직접 지급 · 제안 | 개인 계정의 토큰, 지급 계약에 정확한 금액의 allowance | 지급자 본인이 자신의 계정으로 호출한다. 승인·지급 거래의 가스비는 해당 사용자의 네이티브 잔액에서 지출되며 앱이 각각 표시한다. |

상용 개인 후보에서 토큰 사용 승인과 주문 승인을 별도로 검증한다. allowance만 성공하면 매출 0건이며 중단 시 남은 한도와 철회 경로를 표시한다. 수취 허용 설정, 비상 권한과 환불 재원 책임자를 고정한다. 주소 변경 전후의 견적은 각각 서명된 주소와 현재 유효한 등록 주소가 일치해야 실행할 수 있다.
