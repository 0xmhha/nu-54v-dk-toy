## 사용자와 결과

매장 고객은 공용 단말에서, 근처 고객은 본인 폰에서 동시에 주문한다. 기존 POS 가맹점은 외부 주문 금액만 받아 암호화폐 결제 단말로 쓴다.

## 현재 출발점과 목표 범위

기존 단말에는 메뉴·로컬 주문·BLE 결제·제출 흐름이 있다. 상용 동시 주문, 가맹점 서버 발급과 재시작 복구, 결제 전용 모드를 추가한다. [제품 README](../../../../../products/p04-merchant-kiosk/README.md) · [키오스크 소스](../../../../../products/p04-merchant-kiosk/src) · [가맹점 거래 설계](../../merchant-payments.md)

## 기능과 인수 조건

| ID | 기능 | 제품이 보장할 동작 | 인수 시 관측할 결과 |
|---|---|---|---|
| R1 | 모드·메뉴 | 관리자 설정으로 메뉴/옵션/장바구니가 있는 키오스크 또는 외부 주문 금액만 받는 결제 모드를 선택한다. | 결제 모드에서 메뉴 편집 불가, 진행 중 매매는 모드 전환 뒤에도 조회 가능. |
| R2 | 병렬 주문 | 손님마다 독립 세션·장바구니·픽업 번호를 발급하고 P05에서 재고를 예약한다. 전화 데이터가 없으면 온라인 단말이 BLE 요청을 중계한다. | 한 손님이 5분간 메뉴를 봐도 다른 손님이 먼저 완료. 동시 주문 100건에서 타인 주문 노출·음수 재고 0건. |
| R3 | QR·BLE | 매장·단말·주문·금액을 표시하고 한 지급자로 결합한 견적만 승인에 쓴다. 동적 POS QR은 결합 전 미리보기다. | QR과 BLE로 20회 중복 제출해도 같은 주문에 한 번 지급. RSSI는 탐색 보조로만 사용. |
| R4 | 조회·픽업 | 제출 해시를 저장하고 P07은 체인 확정 증거를 제공한다. P05가 주문·회계·이행 outbox를 한 트랜잭션으로 기록한 뒤 발행한 이행 eventId만 단말 inbox에 한 번 반영해 조리·픽업을 갱신한다. 재접속은 원거래부터 조회한다. | 응답 유실·앱 재기동에도 중복 조리·영수증·재청구 0건. |
| R5 | 데모 운영 | StableNet 테스트넷 지정 토큰만 허용하고 체인·자산·매장·가격·수수료를 사전 표시한다. | 다른 네트워크·토큰을 고르면 승인 단계에 진입하지 않는다. |
| R6 | 점주 현장 운영 | 점주 로그인 후 지점 매출·정산·환불 내역을 조회하고 원주문에서 허용된 환불을 신청한다. 재원·승인·마감은 P05가 처리한다. | 권한 없는 점원은 환불 승인·타 지점 조회 불가. 재원 부족은 접수/지급 대기로 표시하고 확정 영수증을 내지 않는다. |

## 출시 판단

2대 이상 고객 폰과 실제 단말·보드에서 QR·BLE·오프라인 폰 릴레이를 확인하고, 별도 병렬 시험으로 100개 주문을 검증한다. 점주의 일마감은 P05 장부에서 대사한다.

## 공용 세션과 결합 복구

R2·R3·R4의 화면 인수에는 고객 종료, 시간 초과, 재시작을 포함한다. 공용 단말은 이전 세션의 장바구니·연결 표식·주문 식별자·픽업 화면을 지우고 뒤로 가기로 다시 노출하지 않는다. 원주문과 발급된 견적은 서버 및 권한 있는 원래 고객·직원 조회에서 계속 추적한다. POS 직원이 같은 표식을 골라도 P05가 지급자 결합과 견적을 내구 저장한 뒤에만 해당 폰으로 검토를 전달한다. 발급 응답이 유실되면 기존 결합부터 조회한다.
