## 사용자와 결과

별도 클라우드 지갑을 선택한 사용자가 소셜 계정을 연계하고, 분산 키로 서명하며, 휴대폰 분실 시 참여자를 교체한다. 개인 보드의 시드 복구와 대여 기기 승인은 P01의 책임이다.

## 현재 출발점과 목표 범위

제품 디렉터리는 설계 단계다. A(사용자 폰), B(서비스), C(독립 복구 참여자)의 2-of-3 구조는 비교 후보이며 C 운영 주체와 서명 엔진은 미선정이다. ## 기능과 인수 조건

| ID | 기능 | 제품이 보장할 동작 | 인수 시 관측할 결과 |
|---|---|---|---|
| R1 | 생성·연계 | 인증 이후 별도 사용자 증명으로 생성 세션을 예약하고 분산 키 생성(DKG) 완료 후 공개키를 활성화한다. | 중복 요청은 공개 계정 하나, 일부 참여자 실패 시 활성 주소 0개. |
| R2 | 일상 서명 | 허용된 지갑·체인·원문·세대(epoch)·만료를 모바일 별도 승인에 결합한다. 각 참여자는 격리 환경에서 임계 서명한다. | 한 참여자나 로그인 토큰만으로 서명 0건. 결과를 공유해도 완전 개인키 노출 0건. |
| R3 | 복구·갱신 | 독립 복구 확인과 정책상 대기 후 이전 세대를 차단하고 새 참여자 집합의 활성 영수증을 수집한다. | 구세대 재시도·신구 혼용은 거부, 교체 전후 공개키를 유지하는 프로필은 같은 주소로 검증. |
| R4 | 계정 수명주기 | 서비스 장애, 휴대폰 분실, 소셜 연계 해제, 탈퇴를 구분하고 마지막 인증수단 제거를 직렬화한다. | 두 동시 해제에서 마지막 수단이 보존되며 탈퇴 요청이 보드 키나 외부 자산을 움직인 사례 0건. |

## 출시 판단

C의 독립 권한·복구 신원·감사 절차, B+C 결탁 가능성에 대한 운영 통제, 임계 엔진과 장애 시 복구 경로를 검토한 후에만 사용자를 받는다. 기본 하드월렛 출시의 필수 의존성은 아니다.
