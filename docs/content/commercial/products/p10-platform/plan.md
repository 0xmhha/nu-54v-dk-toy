## 제공 순서와 책임

스펙 변경자가 권한·필드·오류 의미와 SDK SemVer·wire major를 따로 정하고, SDK를 생성한 뒤 소비자와 혼합 버전을 시험한다. 배포물마다 실제 검증 조합을 공개한다.

| 단계 · 책임 | 선행 조건과 작업 | 다음 단계로 넘어갈 증거 |
|---|---|---|
| 프로토콜 담당 · 계약 | 관리/지급/근거리 메시지, 버전·역할·식별자·오류 모델을 P01·P02·P04와 확정 | 스키마 diff와 정상/오류 golden vector |
| 통합 QA · 소비자 | C·TS·Go·Python 생성물/ABI 배포, 기존 소비자의 잠금 파일 참조 검증 | 모노레포 밖 독립 C 소비자 빌드·TS tarball 설치, 상호 파싱, 중복·분할·재개, v1/v2 호환 매트릭스 |
| 릴리스 담당 · 배포 | SBOM·보안 공지 대조, 도구체인 고정, 서명·공개 설치·패치 모의훈련 | 빈 보드 설치 기록, 결함 수정 전후 manifests와 실기 회귀 |

## 전환과 장애 대응

취약 종속성은 직접·전이·벤더 복사본까지 영향 경로와 수정본을 추적한다. 패치가 없을 때는 기능 제한·책임자·기한을 기록하고 상용 보안 게이트에 따른다. 중단된 배포는 새 발급을 막고 기존 주문은 원래 도메인에서 대사한다. 부트 롤백 보호를 유지한 복구 이미지를 제공한다.

## 결정이 필요한 항목

SDK 배포 채널·서명자, OS/보드 지원 창, 보안 공지 담당과 패치 SLA는 기존 출시 기준을 적용해 릴리스 manifest에 고정한다. 외부 보안 점검과 실물 공급 검증의 책임자를 지정한다.
