## 진입 구조와 접근 권한

개발자 포털·CLI에 노출할 계약, 산출물, 시험 증거를 기준으로 구조를 정의한다. 운영자의 제품 키와 사용자의 지갑 키는 이 포털의 자료가 아니다.

| 상위 → 하위 | 보이는 정보와 가능한 조작 | 접근 조건과 오류 시 이동 |
|---|---|---|
| 스펙 → 역할/메시지/상태/오류 | 기능 협상·권한·요청/응답·한도 | 소비자는 공개 버전 읽기, 정정은 버전 관리 |
| 배포 → SDK/ABI/manifest/호환표 | 패키지 버전·해시·체인·보드/OS 지원 | 서명·출처 검증 실패 시 가져오기 중단 |
| 검증 → golden vector/시뮬레이터/실기 | 정상·오류·중복·조각·상호운용 결과 | 합성 시험과 실기 증거를 표시, 민감키/PII 제외 |
| 보안·제작 → 공지/SBOM/패치/설치 | 영향 제품·수정 버전·재현 입력·보드 모델 | 공개 검증 자료와 비공개 제보·서명 권한 분리 |
| 서비스 계약 → C1~C9/주체/오류/멱등 키 | API와 메시지별 소유자·테넌트·객체 권한·추적 ID·재시도 의미 | 공개 계약과 실제 고객 로그 분리, 민감 원문 제외 |
| 운영 → 관측/백업/복원 연습 | 체크포인트·보존·복구 시간·대사 차이와 전환 이력 | 운영 책임자와 독립 검증자가 격리 복원 후 승인 |

## 정보 객체와 관계

프로토콜 버전에서 스키마 해시·생성기·SDK·벡터로 추적한다. 제품 릴리스는 SDK/ABI/도구체인·대상 보드/OS·SBOM·빌드 증명 참조를 담는다. 계약 주소와 서명 도메인은 네트워크와 함께 식별한다.

## 상태와 복귀 위치

호환표는 합성 벡터 통과와 보드·OS별 실물 증거 확보를 별도 항목으로 제시한다. 출처 검증 실패와 미지원 조합에서도 공식/커스텀 채널을 보존한다. 복원 작업자는 격리 복원을 요청할 수 있고 승격 결과는 독립 검증자의 승인과 실제 전환 확인 뒤 표시한다. [조합별 증거](../../screens/book.html#D03) · [복구 승격과 역할](../../screens/book.html#D06)

제안 → 생성·검토 → 호환 검증 → 서명 배포 → 지원/지원 종료. 취약점 접수 → 영향 분석 → 수정/완화 → 재검증 → 공지. 사용자에게 표시하는 지원 상태와 내부 후보 빌드를 분리한다.
