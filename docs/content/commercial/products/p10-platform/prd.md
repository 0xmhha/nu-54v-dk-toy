## 사용자와 결과

펌웨어, 모바일, 키오스크, 운영 서비스 개발자가 같은 프로토콜과 검증 자료를 가져다 쓰고 어느 릴리스 조합이 함께 동작하는지 판단한다. 커스텀 보드 제작자는 동일 절차로 자기 빌드를 검증한다.

## 현재 출발점과 목표 범위

공유 프로토콜 패키지, 언어별 생성물, 적합성 harness와 12주 수용 스크립트가 있다. v2 협상·신뢰·상용 배포 및 부품별 보안 패치 증거는 추가할 목표다. [제품 README](../../../../../products/p10-platform/README.md) · [독립 프로토콜 프로젝트](../../../../../packages/protocol/README.md) · [프로토콜 상호운용](../../protocol.md) · [공급망·출시](../../security-and-release.md)

## 기능과 인수 조건

| ID | 기능 | 제품이 보장할 동작 | 인수 시 관측할 결과 |
|---|---|---|---|
| R1 | 공통 스펙·배포 | 별도 버전의 스키마·생성기·C/TS/Go/Python 산출물을 제공하고 P01/P02/P04가 같은 릴리스에서 import한다. | 동일 벡터의 프레임·직렬화 바이트 일치, 앱/펌웨어 빌드가 참조한 버전을 manifest로 역추적 가능. |
| R2 | 역할·세션 | 관리(폰↔보드), 지급(단말↔보드), 근거리 주문(폰↔단말)의 권한과 상태를 분리하고 협상·만료·재생·중복·조각 복구를 정의한다. | 소유자 앱과 가맹점 단말 양쪽의 `pay.prepare`가 같은 가맹점 서명 견적을 검증한다. 잘못된 역할·순서·구버전 강등은 거절. 분할·중복·재연결 시 다른 세션의 승인 0건. |
| R3 | 릴리스·보안 | 펌웨어/앱/계약/서버 전이 종속성과 도구를 목록화하고 SBOM·권고 매칭·패치·빌드 증명·서명·회귀 증거를 릴리스에 연결한다. | 영향받는 버전 확인→수정 버전 고정→재스캔→재현 빌드와 회귀→지원 채널 배포 이력이 이어진다. |
| R4 | 호환·수용 | 보드/OS/SDK/ABI/계약 주소·체인 ID 조합을 기록하고 테스트넷용 모의 벡터와 실기 증거를 구분한다. | 부트 이미지 오류·지원 외 조합은 활성화 전 발견, v1 지정 대여 업무는 계속 지원하며 v2 전용 개인 서명·직접 지급 요청의 v1 강등은 거절한다. |
| R5 | 공개 설치·커스텀 | 재현 가능한 빌드 지침, 지원 보드/BOM·핀맵·부트 신뢰 루트, 커스텀 배포 표시와 보안 업데이트 경로를 제공한다. | 제3자가 빈 보드에서 제시된 입력으로 빌드·검증·설치하고 다른 루트의 이미지 혼입을 거절. |
| R6 | 서비스 계약과 재해 복구 | C1~C9의 인증·인가, 공통 ID·오류·추적과 멱등성, 백업·복원·관측 규약을 버전별로 관리한다. | 다른 테넌트 접근 거절, 같은 키·다른 본문 충돌, 복원/재생 후 중복 업무 효과 0건 및 합의된 복구 목표 실측. |

## 출시 판단

프로토콜 릴리스는 최소 P01↔P02 설정과 P01↔P04 결제, P02↔P04 주문의 상호운용 기기 로그를 요구한다. 알려진 취약점 처리·재현 빌드·키 교체 절차는 버전 단위로 추적한다.
