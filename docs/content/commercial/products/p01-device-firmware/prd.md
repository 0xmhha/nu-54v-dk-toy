# P01 보드 펌웨어 · 제품 요구사항

[제품별 설계 목차](../README.md) · [PRD](prd.md) · [기획](plan.md) · [유즈케이스](use-cases.md) · [정보구조](ia.md)

## 사용자와 결과

보드를 직접 구입한 소유자가 검증한 펌웨어를 설치하고 자산 키를 생성·복구·사용한다. 대여 현장에서는 운영자가 지급한 기기를 여행자가 정해진 범위 안에서 사용한다. 두 프로필은 별도 키 슬롯과 관리 정책을 갖는다.

## 현재 출발점과 목표 범위

현행 Zephyr 앱은 설정과 결제 링크, 보드 버튼·LED, PSA 키를 사용한다. 기존 설정 PIN 전달 방식과 단일 서명 경로는 상용 v2로 전환할 대상이다. [제품 README](../../../../../products/p01-device-firmware/README.md) · [보드 설정·키 코드](../../../../../products/p01-device-firmware/app/src) · [모바일과 지갑의 신뢰 경계](../../wallet-and-mobile.md)

## 기능과 인수 조건

| ID | 기능 | 제품이 보장할 동작 | 인수 시 관측할 결과 |
|---|---|---|---|
| R1 | 설치·등록 | 지원 보드 ID, 부트 서명 및 버전을 검사하고 소유 증명 후 기기 식별 키로 등록한다. 지갑 생성은 그 다음이다. | 변조 이미지·다른 모델·롤백을 거절하고 전원 중단 뒤 재개해도 두 번째 루트가 생기지 않는다. |
| R2 | 잠금·서명 승인 | PIN은 보드에서 입력한다. 원문에서 수취인·금액·수수료·네트워크·권한을 추출하고 1회 버튼 입력을 동일 요청에만 묶는다. | 잠금·기기 분리·만료·내용 변경 후 이전 버튼 입력으로 서명 0건. BLE 기록에서 PIN 각 자리를 복원할 수 없다. |
| R3 | 멀티체인 | Bitcoin의 입력·거스름돈, Ethereum·Base·StableNet의 네트워크와 호출, Solana의 instruction, XRPL의 금액·태그를 해석한다. 파서와 서명 방식은 체인별로 등록한다. | 여섯 네트워크별 주소 파생·전송을 독립 벡터와 대조하고 미지원 형식·알 수 없는 호출을 거부한다. |
| R4 | 개인 백업·복구 | 독립된 신뢰 입력·표시 수단에서 백업을 기록하고 새 보드에서 복원한다. 폰 교체는 보드 PIN과 독립 복구 증명을 요구한다. 지갑 루트는 유지하고 소유자 앱 공개키·권한 세대를 원자적으로 교체하면서 옛 대기 승인을 폐기한다. | 새 보드의 파생 주소가 원본과 일치하고 복구 문구의 BLE·앱·로그 유출 0건. 분실 보드 위험과 새 루트 이전을 안내한다. |
| R5 | 대여 반납·개인 초기화 | 대여 종료 권한은 대여 슬롯에 한정한다. 개인 루트 삭제와 자가 서명 루트 전환에는 별도 물리 확인과 복구 수단이 필요하다. | 대여 반납으로 개인 키가 삭제되거나 승인되지 않은 개인 송금이 발생하는 사례 0건. |
| R6 | 계정 재발견·고급 승인 | 계정·주소 유형별 재발견과 선택적 읽기 전용 xpub/descriptor 내보내기를 별도 동의로 제공한다. PSBT 공동서명은 등록 정책·서명자·거스름돈 검증 후, EVM 권한 변경은 spender·금액과 독립 표시 정책 확인 후 허용한다. | 타 지갑 descriptor·위장 거스름돈·불명확한 allowance 거절. 복원한 계정에서 같은 주소를 재발견한다. |

## 출시 판단

상용 개인 지갑 게이트는 보드별 키 격리·엔트로피·독립 복구·고위험 거래 표시를 실기로 입증하는 것이다. 그 전에는 지정 테스트넷 또는 별도 승인된 제한 프로필만 시연한다.
