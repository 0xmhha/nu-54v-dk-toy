## 제공 순서와 책임

제작자는 보드 이력과 이미지를 확인하고, 소유자는 폰을 결합한 뒤 키를 생성한다. 일상 결제와 분실 복구를 서로 다른 기기 조합으로 인수한다.

| 단계 · 책임 | 선행 조건과 작업 | 다음 단계로 넘어갈 증거 |
|---|---|---|
| 보드 담당 · 부트와 등록 | 지원 리비전·핀·저장공간을 확인하고 P10 manifest와 등록 전용 키를 연결 | 빈 보드 설치, 잘못된 이미지 거절, 중단 복구 기록 |
| 지갑 담당 · 키·파서 | 개인/대여 격리와 버튼 승인 정책을 확정한 뒤 P02·P10과 서명 벡터 교환 | 6체인 정상/오류 원문, 의도한 수취인 일치, 보드별 메모리 실측 |
| 보안·QA · 복구와 출시 | P02와 폰 분실/보드 분실을 따로 연습하고 독립 표시 수단 검증 | 백업 복원 주소 대조, 구 본드 차단, 고위험 요청 차단 및 복원 로그 |

## 전환과 장애 대응

서명 대기를 RAM에서 지우고 실패 카운터·활성 키 슬롯은 원자적으로 기록한다. v1 대여 보드의 키를 개인용으로 승격하지 않는다. 장애 복구 시 서명 결과를 조회할 수 없으면 자동 재승인하지 않는다.

## 결정이 필요한 항목

제품 보드 리비전별 보안 저장 수단, 독립 표시·복구 액세서리와 공급 경로를 실측 후 선정한다. 지원 조합과 허용 거래 위험 등급은 출시 manifest에 고정한다.

## 기존 보드 기능과 공존

대여 TimeAnchor·패스키, 오디오 전송, 기기 찾기와 FOTA는 지원 리비전별 capability로 표시한다. 서명과 패스키 승인이 겹치면 버튼 소유자가 하나만 남고 다른 요청은 대기/거절된다. FOTA 적용은 승인 세션과 녹음·전송을 안전 종료하고 전원·manifest·사용자 승인을 재확인한 뒤 수행한다. 서명 도중 업데이트, 오디오 버퍼 부족, 전송 중단·재개를 실기 인수에 포함한다. [기기 자원과 FOTA 공존](../../../specifications/device-coexistence-design.md)

### 업데이트 화면에서 기기 전원을 확인하는 경로

기준 회로도 NU-54DK-C의 1·3쪽에서 충전기 BQ25186의 `/PG`는 SB2를 거쳐 P2.08에, 배터리 전압 분압 출력 `VBAT_MON`은 SB4를 거쳐 P1.12에 연결된다. USB와 외부 전원 입력은 다이오드 뒤에서 합쳐진다. 따라서 이 전원 경로에서 확인할 수 있는 표시는 ‘외부 입력 감지’다. 장치 트리에는 `pmic-pg-gpios`와 `vbat`가 정의돼 있다. 설치된 보드의 실제 리비전·부품·브리지 상태는 실기 단계에서 확인한다. [고정 회로도와 보드 참조](../../../../../products/p10-platform/release/board-reference.json) · [P01 핀 설정](../../../../../products/p01-device-firmware/boards/nucode/nu54v_dk/nu54v_dk_nrf54l15_cpuapp_ns.dts)

| 조건 | 펌웨어와 모바일의 처리 |
|---|---|
| 지원 리비전에서 현재 외부 입력 조회 | 상태 읽기만 수행한다. BQ25186의 현재 입력 유효 상태와 `/PG`를 대조할 경우 핀이 전원 상태 출력 모드인지도 확인한다. 충전 전류 설정이나 읽으면 사라지는 이벤트 플래그에는 접근하지 않는다. [TI BQ25186 상태·설정 레지스터](https://www.ti.com/lit/ds/symlink/bq25186.pdf) |
| 외부 입력 없음, 읽기 실패, 리비전 미지원 또는 측정 불일치 | 확인된 입력 없음과 확인 불가를 구분하고 업데이트 준비를 보류한다. 배터리 전압 한 번의 측정으로 잔량이나 업데이트 가능 시간을 추정하지 않는다. |
| 업데이트 재진입·연결 상실·실제 적용 직전 | 현재 보드의 전원을 다시 조회한다. 버전·후보 서명·작업 충돌·물리 승인도 각자의 근거로 확인한다. 원격 운영 로그에 전원 측정 이력을 추가하지 않는다. |

### 오디오 전송 재개

W12의 진행 수치는 휴대전화가 저장을 끝낸 연속 구간으로 계산한다. BLE 프레임 수신만 확인했거나 같은 프레임을 다시 받으면 수치를 올리지 않는다. 재접속하면 원래 녹음 식별자와 소유·동의·스트림 세대를 다시 대조한다. 휴대전화가 확인한 다음 구간이 보드 RAM에 남아 있으면 전송하고, 이미 버퍼에서 사라졌으면 누락 구간을 표시한다. 보드 플래시에 원음을 복사하거나 녹음을 자동으로 다시 시작하지 않는다. 동의 철회나 소유자 전환 뒤에는 과거 스트림에서 지연된 응답이 와도 전송을 중단한 상태를 유지한다.

현재 개인 보드의 기능 응답은 LED 찾기와 취소를 제공한다. 휴대전화의 상태 읽기는 별도의 로컬 음성 안내다. 오디오 리비전의 완료 근거는 동의한 스트림의 중복·누락·중단·재개 및 저장 확인을 W12에서 대조하는 시험이다. [기기 자원과 전송 실패 사례](../../../specifications/device-coexistence-design.md#dc-t09) · [W12 화면 흐름](../../screens/specs/W.md#w12--기기-유지관리와-반납)
