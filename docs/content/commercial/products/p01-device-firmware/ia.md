## 진입 구조와 접근 권한

기기에는 화면이 없다. 아래 구조는 버튼·LED, BLE 상태, 짝지은 폰 또는 독립 액세서리가 각각 무엇을 노출하는지 정한다.

| 상위 → 하위 | 보이는 정보와 가능한 조작 | 접근 조건과 오류 시 이동 |
|---|---|---|
| 부트 → 설치/복구 | LED로 준비·오류, 폰에서 모델/이미지 버전과 재시도 절차 | 부트 검증 실패는 복구 모드 |
| 기기 → 소유권/잠금 | 보드 로컬 입력과 성공·잠금 결과, 폰에는 상태만 표시 | 등록 전에는 관리 기능을 제한, 실패 한도 후 복구 |
| 지갑 → 계정/거래 | 계정 공개 주소, 원문 요약, 승인/거절 상태 | 고위험은 독립 표시, 권한·기능 불일치는 거래 거부 |
| 유지관리 → 업데이트/반납/초기화 | 프로필, 신뢰 루트, 삭제 대상 및 보류 지급 | 대여 운영자와 개인 소유자 메뉴를 구분, 중단 시 복구 |

## 정보 객체와 관계

기기 식별 키는 지갑 루트와 생애주기가 다르다. 한 루트에 체인·계정·경로를 연결한다. 대기 요청은 원문 해시·세션·만료·위험 등급을 참조한다. 비밀 키는 기기에 남는다. 외부에 보내는 값은 용도에 따라 공개 주소·소유 증명·승인된 서명으로 제한하고, 여러 주소를 연결할 수 있는 xpub/descriptor 내보내기는 범위를 표시해 별도 동의를 받는다.

## 상태와 복귀 위치

미설정 → 소유자 결합 → 지갑 준비 → 잠금/해제 → 승인 대기 → 서명/거절. 연결 해제는 대기와 잠금 상태를 정리한다. 구 보드 복구와 구 폰 재결합은 다른 진입점이다.

### 기기 상태를 확인하는 화면

설치 상태는 W03, 소유 결합과 로컬 입력 결과는 W04에서 조회한다. W06에서 폰 교체와 보드 복원을 선택한다. W12에서 실행 슬롯·부가 기능·대여 정산을 확인하며 개인 삭제와 신뢰 루트 변경은 각각 별도 확인 단계를 사용한다. W16과 W17에서는 공개정보 내보내기와 공동서명 정책을 독립적으로 검토한다. 휴대폰의 탐색 버튼과 보드가 보낸 승인·거절 이벤트를 개별 상태로 기록한다.
