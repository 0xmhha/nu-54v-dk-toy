## 진입 구조와 접근 권한

지점이 조회의 기본 범위다. 고객용 메뉴와 운영 메뉴를 분리하고 모든 결제 현황에서 원주문, 체인 증거, 감사 이력으로 이동할 수 있게 한다.

| 상위 → 하위 | 보이는 정보와 가능한 조작 | 접근 조건과 오류 시 이동 |
|---|---|---|
| 가맹점 → 지점/직원/단말/지급 주소 | 자격 발급·회수·주소 변경 대기 | 점주·보안 승인자, 점원은 읽기 범위만 |
| 상품 → 메뉴/옵션/가격표/재고/시간대 | 편집본·게시 버전·예약 가능 수량 | 카탈로그 담당자, 충돌 시 버전 비교 |
| 영업 → 주문/예약/구독/픽업 | 주문 전이·회차·가격 근거·이행 상태 | 지점별 담당, 개인 고객은 자신의 주문만 |
| 재무 → 지급/환불/일마감/차이 | 실지급 주소·원금/환불/순액·가스·증거 | 재무 역할별 신청·승인 분리, 차이는 조사 큐 |
| 운영 → 대여/단말 장애/감사/outbox | 대여 반납, 실패 통지, 재시도·이력 | 전용 운영자, 재시도로 원결제를 새로 발급하지 않음 |

## 정보 객체와 관계

매장 아래 지점·단말·메뉴 버전, 주문 아래 지급자 claim·견적·시도·확정 지급·환불 목록이 있다. 예약 하나가 디파짓과 잔금 각각의 별도 orderId를 참조한다. 두 주문은 각각 자체 견적·지급·환불 한도를 가지며 예약에서 합계를 확인한다. 청구서는 구독·회차와 해당 주문을 연결한다. 체인 증거와 업무 처리 상태를 별도로 저장한다.

## 상태와 복귀 위치

주문 작성 → 재고 예약 → 견적 발급 → 확인 중 → 지급 확정 → 이행. 미지급 만료가 확정되면 재고를 해제하고 미이행 종료한다. 환불·구독 해지·대여 반납은 각자의 상태를 가진다. 마감 후 추가 증거는 조정 항목으로 남기고 과거 내역을 덮어쓰지 않는다.

## 운영자별 복구 화면

환불은 원주문 → 신청 검토 → 승인 대기 → 별도 재원 운영 검토 → 제출 결과 조회 → 체인과 장부 확정 순서다. 승인 자격은 신청 이후에도 서버에서 확인한다. 정산 마감은 영업일·지점·자산 범위를 전송과 내보내기에 유지하고 서버에서 최신 대사 차이를 다시 확인한다. 차이 조사에는 원주문·체인 증거·변경 시각·POS 통지 ID·같은 ID 재처리 결과를 표시한다. 대여 운영자는 원 계정의 미결 지급과 검증된 반환 경로를 보고 반납 후 정리 요청을 별도로 진행한다.
