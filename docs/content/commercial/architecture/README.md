# 상용 제품의 데이터·기능 설계

**원본 사실마다 최종 쓰기 권한은 한 곳에 있다.** 좌석을 확보한 사실은 P05, 돈이 이동한 사실은 P06의 체인, 그 사실을 어떤 블록까지 검증했는지는 P07이 소유한다. P02와 P09가 같은 예약을 보여도 좌석이나 지급 원장을 하나 더 만들지 않는다. 사용자가 보드 버튼을 누른 시각·서명 제출·가맹점 실수령·픽업 발급은 각각 다른 상태다. 이 문서를 상용 구현의 기준으로 사용하고 PoC는 구버전 호환·이관·회귀 시험의 입력으로 사용한다.

## 값의 식별과 이동

개인 지갑은 회원 가입 없이 보드와 폰에서 시작한다. 선택형 MPC와 여행 계정은 각 서비스에 발급한 별칭을 사용한다. 동일 사용자를 묶는 전사 행, 서버 주소록, 위치와 결제의 결합 분석 테이블을 두지 않는다. 공개 체인의 주소가 업무에 꼭 필요하면 해당 거래 도메인의 검증 영역에만 둔다. SQL에서 다른 소유자의 키처럼 보이는 참조는 권한 토큰이 아니다. 서비스 간 수신자는 발급자·대상·목적과 객체 접근을 다시 검증한다.

| 값 | 생성·검증 규칙 | 재사용의 범위 |
|---|---|---|
| 작업 키·명령 해시 | 불투명 난수; 소유 영역·테넌트/주체·명령에 묶고 스키마 버전 포함 canonical hash를 비교한다. 범위는 DB 키 또는 도메인 접근 함수로 강제 | 동일 키와 내용은 원래 결과, 다른 내용은 충돌. 조회자가 바뀌면 권한부터 확인 |
| 자산과 금액 | 네트워크/배포·자산 식별자와 최소 단위 정수, 파서에서 음수·소수·타입 최대값 초과 거절. XRPL 발행 통화는 [정확한 계수·스케일](wallet.md) 적용 | display decimals·환산 시세·문자열 ticker를 서명 입력으로 복원하지 않는다 |
| 시간과 관측 | 서비스 시각은 UTC 순간, 영업일/예약 표시는 지점 시간대, 발급의 만료·체인 포함/확정과 수집 시각을 분리 | 늦은 확정과 이미 발급한 주문은 원본 재조회. 철회·삭제는 목적별 세대와 시점 경계로 판정 |
| 거래·개인 참조 | 업무 ID, 체인 order key, 임시 claim, 상담/감사 ID마다 수명/권한 구분. 값이 공개되더라도 고객 상세를 읽을 수 없게 객체 권한 검사 | 필요한 경계에서만 위임, 외부 푸시·QR·BLE 광고·로그에 고객별 장기 식별자 전파 금지 |
| 원본·파생물 | 원본 소유자와 버전/확정 증거를 지정. 비식별 공개 사양 및 합성 벡터는 공개, 구매내역·가명 매핑은 제한, 시드·PIN·지분은 비밀 경계 | 읽기 모델·캐시·백업·내보내기·공급자 임시본에도 같은 접근·만료와 정정/삭제 사건 적용 |

## 스키마 사용과 전환 기준

설계 DDL을 제품별 마이그레이션으로 옮기는 순서와 파일럿 전환·복구 기준은 [구현 및 리팩토링 계획](../implementation-plan.md)에 있다.

[wallet.sql](schema/wallet.sql), [ledger.sql](schema/ledger.sql), [experience.sql](schema/experience.sql), [platform.sql](schema/platform.sql), [privacy.sql](schema/privacy.sql)은 빈 PostgreSQL에서 각각 적용할 수 있는 설계 DDL이다. 한 임시 DB에서 함께 실행해도 저장소 사이의 FK는 없다. 실제 배치에서는 보드 NVM, 폰의 보호 저장소, P03 격리 지분 저장, P06 체인, 서비스별 DB·객체 저장·KMS·감사 보관을 각 소유 경계에 둔다. 키 원문을 테스트 DB로 옮길 필요가 없다. SQL의 FK/unique/check로 검증하는 조건과 권한·서명·시간·이전 상태·교차 행 합계처럼 명령 트랜잭션에서 검증할 조건은 도메인 문서에 나눠 썼다.

검증 경로는 **빈 DB에 DDL 적용 → [카탈로그에서 ERD 생성](schema/erd.psql) → [합성 제약 시험](schema/checks.sql) → 도메인별 경쟁·실패/재시도 시험 → 화면 수용 증거** 순서다. 장치·체인·사용자 보호 통제의 실제 동작은 각각의 구현과 운영 환경에서 증명해야 한다. PoC 원문에 있는 추가 데이터나 넓은 API 스코프는 자동 승계하지 않는다.
