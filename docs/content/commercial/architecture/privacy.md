# 개인정보 처리 설계와 ISMS-P 운영 증거

국내 다중 가맹점 파일럿을 기본 배치로 설계했다. 보드 자가 설치, 모바일 OS, 가맹점 운영자, 서비스 운영 법인, 장소·푸시·AI 수탁자의 실제 책임과 국가를 처리 흐름마다 확정한다. 출시 책임자는 처리방침, 수탁·제3자 제공 관계, 국외 이전 근거, 보유기간 및 행사 창구가 실제 배치와 일치하는지 확인한다. 점검 근거는 정부 인증기준 안내서, 개인정보 보호법과 안전성 확보조치 기준이다. 이 문서의 판단 대상은 목표 설계이며 인증에는 운영 증적과 심사가 필요하다. **법적 근거 결정.** 처리자는 계약 이행·법적 의무·선택 동의 등 실제 근거를 목적별로 기록하고 강제 필드의 필요성을 입증한다. 여행 기록 거부 시 수동 검색·결제는 제공한다. 속성 하나를 서로 다른 근거로 유지할 수 있으면 범위·접근을 분리하고 파기 예정일을 따로 둔다. 위치기반 서비스, 금융/상거래 기록, 미성년 이용 가능성, 민감정보를 드러낼 수 있는 음성·이동경로는 서비스 공개 전에 해당 제도와 적용 주체를 판정한다. 만 14세 미만에 법정대리인 동의가 필요한 기능은 그 경로를 검증할 때까지 제한하고 전 사용자에게 신분증을 수집하지 않는다. 제공자의 학습·재사용·하위수탁·역외 백업·삭제 증거 조건이 미확정이면 해당 선택 기능을 보류한다. **고객용 거래 조회 필드.** W09는 인증된 지점·고객의 현재 조회권에 따른 주문과 회차를 연결한다. W11의 원주문 UUID·제출 단계·거래 해시·체인 포함 시각·영수증·픽업 진행은 지급과 이행을 확인하는 데 사용한다. 지급 증거는 활성 등록의 원지급자에게만 같은 주문 조회 응답으로 보낸다. 주문 링크와 알림에는 개인 결제 상세를 넣지 않는다. 고객 화면은 거래별 조회 권한과 기한을 다시 확인한다. 별도의 지급 조회 사본을 서버에 만들지 않으며 원장 보존은 위 P04/P05 기준을 적용한다. 앱의 미결 승인 기록은 보호 저장소에서 등록과 지점별로 분리하며 확정이나 종료 후 원래 요청을 정리한다. [원천 관계와 필드](../../../../products/p05-operations-backoffice/COMMERCE.md#고객용-원지급-조회)

P05 반납 원장의 운영자 참조·서명자 주소·거래 해시는 지점의 대여 사건과 연결되는 제한 데이터다. 확정 전에 같은 거래를 다시 전송하기 위해 보관하는 서명 원문은 데이터베이스 외부에서 관리하는 키로 인증 암호화한다. DB에는 개인키를 저장하지 않는다. 전용 실행 역할만 현재 지점·담당자·원검토를 확인한 뒤 보호 함수를 통해 재시도할 수 있다. 운영 로그·통지에는 서명 원문을 보내지 않는다. 거래 종결 시 암호문을 파기하고, 대사용 해시와 원요청 참조는 지점의 승인된 보유기간 종료 후 파기한다. 대기 중 거래가 있으면 키 교체·백업 복구 시 같은 해시로 재개할 수 있어야 한다. ## 보호 통제와 권리 처리

1. **권한 경계**. 사용자는 자신의 서비스별 별칭, 가맹점은 지점·행위·객체, 운영자는 승인된 업무 범위로 조회한다. 모든 reader/worker와 내보내기에도 같은 필터를 적용한다. IdP의 검증된 issuer/audience와 scope로 인증하고, 담당자 변경·퇴사 시 IdP 자격과 지점 역할을 함께 회수한다. 긴급 접근은 MFA, 사유, 짧은 만료, 사후 독립 점검이 필요하다. 데이터 관리자, KMS 관리자, 감사 조회자를 나눈다.
2. **암호화와 파생 데이터**. 서비스별 KEK, 데이터 분류·테넌트별 DEK, 암호화된 DB/객체·백업, TLS와 자격 수명 제한을 적용한다. 키 식별자·버전만 레코드에 둔다. 접근 통제와 만료는 캐시·CSV·검색 색인·객체 버전·작업 큐에도 적용한다. 백업 키 회전과 복호 시험을 시행한다. 민감 데이터는 표준 출력, SDK 분석 이벤트, 코어 덤프, AI 훈련 집합으로 복사하지 않는다.
3. **권리 요청**. 앱에서 목적별 열람/정정/삭제·처리정지/동의 철회 또는 적용되는 전송 요구를 선택한다. 보유한 기기/권한의 재증명이나 복구 절차로 본인을 확인하고 지갑 시드·신분증의 상시 수집을 피한다. 요청 원장은 서비스별 별칭, 요청 유형, 범위와 기준 revision, 접수·기한, 처리 담당/결과, 이의제기 경로를 기록한다. 정정은 원장 정정 전표, 공개 체인 설명, 선택 기록 교정을 구분한다. 보존 의무가 남으면 사유·근거·만료와 이의 절차를 통지하고 해당 자료의 이용을 제한한다.
4. **삭제와 복구**. 철회 시점에 송신/저장을 차단하고 선택한 대상과 하위 파생물, 수탁자, 푸시, 검색 캐시, 백업까지 작업으로 분해한다. 삭제 대장은 원본 업무 백업 외부에 서비스별 객체 토큰·세대·cutoff·만료만 유지하고 최장 복원 가능 백업과 전달 재시도 기간을 모두 넘긴 뒤 파기한다. 재동의 후 생성한 새 세대와 분리한다. 만료 전 백업은 격리하고 복원 직후 대장을 먼저 재적용한다. 공급자가 응답하지 않거나 기기가 오프라인이면 완료 영수증을 내지 않는다. [T12 대상별 삭제](../screens/book.html#T12) · [D06 복원](platform.md)
5. **접속기록과 일반 로그**. 개인정보처리시스템 접속기록은 분리된 변조 방지 저장소에 취급자 식별자, UTC 접속일시, 실제 접속지 정보(암호화), 처리 대상 정보주체를 특정할 수 있는 범위 한정 참조, 수행 업무·내려받기, 결과를 보관한다. 참조 변환 권한은 감사자에게만 부여한다. 여러 정보주체를 처리한 경우 제한된 대상 명세를 별도 보관한다. 원본 개인정보와 지갑 키·자유서술은 기록하지 않는다. 삭제·변경 금지 역할, WORM 또는 동등 보관, 별도 검증 키, 누락·변조·시계 이상 경보, 접근 기록 자체에 대한 조회 감사가 필요하다. 제8조에 따른 기본 1년 이상, 5만명 이상 시스템·고유식별정보 또는 민감정보 처리 시스템·해당 기간통신사업자 등 적용 조건에서는 2년 이상을 정책으로 고정한다. 다운로드·대량 접근·권한 변경을 내부 관리계획 주기로 점검하고 이상 시 원인·조치를 남긴다. 이 기간은 사용자의 BLE·검색 이력에 적용하지 않는다. [개인정보의 안전성 확보조치 기준 제2조·제8조](https://www.law.go.kr/admRulInfoP.do?admRulSeq=2100000281400)

대상별 적용성, 예외의 근거와 책임자, 자료 유형별 법정 기산점·기간, 수탁자 계약·국가, 접근기록 점검 주기, 침해 대응 연락·훈련 실적은 실제 운영 주체가 확정한다. 서비스 구성과 적용 기준이 바뀌면 표를 다시 검토하고 근거가 달라진 데이터는 이관하거나 파기한다. [정부 인증기준 안내서](https://www.privacy.go.kr/front/bbs/bbsView.do?bbsNo=BBSMSTR_000000000049&bbscttNo=20677)

[통제 저장소 DDL](schema/privacy.sql)은 처리자·서비스 범위 안에서 보유 기준 버전, 접속기록 색인과 권리 접수 상태를 표현한다. 실제 접속지 암호문과 대상 명세는 별도 키로 보호하고 업무 계정에 읽기 권한을 주지 않는다. 책임자가 정책 시행일에 검증한 보유기간을 사건별 keep_until로 고정한다. 접근기록 업무 계정은 추가 전용, 보존기한 집행은 별도 파기 역할과 이중 승인, 변경 흔적은 외부 불변 보관으로 확인한다. 여러 서비스의 권리 접수는 사용자가 선택한 범위에서 각 서비스 영수증만 집계한다. 권리 창구는 보드 비밀이나 모든 구매내역을 모으지 않는다. P09 목적별 삭제의 범위·기준 세대·대상 완료는 P09가 보관한다.
