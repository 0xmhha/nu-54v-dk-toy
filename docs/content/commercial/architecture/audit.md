## 실행해 확인한 범위

- PostgreSQL 15의 빈 검증 DB에 [설계 DDL](README.md) 5개를 함께 적용했다. 8개 스키마, 79개 테이블, 89개 FK를 카탈로그에서 [ERD·필드 사전](erd.md)으로 생성했다. 보드·모바일·온체인 저장소도 각 도메인의 논리 모델로 별도로 검토했다.
- [합성 데이터 회귀](schema/checks.sql)는 트랜잭션을 롤백한다. 동일 명령 중복, 환불의 같은 요청 재시도/다른 본문·한도·자기 승인, 동시 활성 키 세대, 테스트넷 밖 시장, 소수 금액, 위치 동의로 음성 저장, 미발급 동의 세대 사용, 복원 작업자의 자기 승인과 승인 없는 전환, 접근기록의 대상 누락을 검사했다.
- 별도 PostgreSQL 세션 두 개로 같은 원금 30에 각각 20을 신청했다. 첫 거래가 지급 행을 잠근 상태에서 두 번째 거래가 실제 DB 잠금 대기에 들어간 것을 확인했다. 첫 거래 커밋 후 신청 한 건만 예약되고 누계는 20이었다.
- 기능 처리표의 화면 ID 집합과 카탈로그가 86개 모두 일치한다. 461개 상태와 96개 PRD·UC 참조의 화면집 재생성 일치 및 주요 전환 회귀 검사를 통과했다. 문서의 Mermaid 20개를 네트워크가 꺼진 Chromium에서 렌더링했다.

## 구현·운영 승인에 남기는 항목

DDL에는 타입, 키, 참조·유일성, 일부 상태 조건을 구현했다. 상태 변경 권한·역할, 참조된 체인/자산·시간·서명의 진위, 기관 간 삭제 확인, 보드·폰의 BLE 신뢰 경계는 서비스·기기·수탁자에서 시험해야 한다. 실제 운영의 자격/암호키·ISMS-P 심사·보유근거와 관할·실기 무선 관찰·상용 체인 지급·재해 복구는 이번 문서 감사의 합격으로 대체할 수 없다. [릴리스 게이트](../security-and-release.md) · [개인정보 운영 증거](privacy.md) · [BLE 실기 인수](security.md)
