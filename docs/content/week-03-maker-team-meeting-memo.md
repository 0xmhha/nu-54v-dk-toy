## 1. 우리 팀이 만들 것, 한 문장

카페에서 스테이블코인으로 결제하려는 외국인 여행자가 키오스크에서 주문할 때, 손에 든 기기에 매장과 금액을 보여 주고 버튼 한 번으로 테스트넷 결제를 승인하게 해주는 것.

- 팀원 문장 비교: [ ] (여행 발자취·대여·AI 추천을 한 문장에 넣자는 의견이 나오면 "첫 결제 이후 확장"으로 분리한다)

## 2. 모듈 구성

| 자리 | 모듈 | 맡는 일 | 상태 |
|---|---|---|---|
| 입력 | 물리 버튼 (보드 기본 버튼 → 이후 외장 버튼) | 결제 승인·거절 | 보드 핀 미확인 |
| 입력 | BLE (키오스크·앱 → 기기) | 주문 ID·매장·금액·만료 시간 수신 | 미시험 |
| 처리 | NU40 / NU-54V-DK (nRF54L15, Zephyr) | 요청 검증, 만료·중복 판정, 기기 안 키로 서명 | 보드 타깃 미확인 |
| 출력 | 소형 디스플레이 | 매장명·금액·남은 시간 표시 | 모델·인터페이스(SPI/I2C) 모름 |
| 출력 | LED (+ 진동 모터 선택) | 대기·승인·실패 상태 알림 | 보드 LED 미확인 |
| 출력 | BLE (기기 → 키오스크·앱) | 서명 결과·오류 전달 | 미시험 |
| 전원 | 배터리·충전 모듈 | 휴대 동작 | 모름 |

바깥 시스템: 키오스크(Android 태블릿, React Native) → StableNet 테스트넷(대체 USDC) → Indexer → 키오스크 영수증·사용자 앱.

4주차에 물어볼 모듈: 디스플레이 모델과 연결 방식, 배터리·충전 모듈, 진동 모터 구동 방법.

## 3. 동작 흐름 한 줄

켜짐 → BLE 광고 → 키오스크와 결제 세션 연결 → 주문(ID·매장·금액·만료) 수신 → 화면 표시 → 버튼 승인/거절 → 기기 안에서 서명 → 키오스크가 테스트넷에 제출 → Indexer 확정 → 키오스크 영수증 · 앱 결제 기록

- 무엇으로 재는지: 같은 주문 ID가 기기·체인·Indexer·키오스크에서 같은 결과로 보이는지
- 아직 못 정한 기준: 요청 만료 시간 [ ]초, 버튼 길게 누름 [ ]초, 확정으로 볼 블록 수 [ ]

## 6. 막힐 것 같은 지점 3개

1. Zephyr 보드 타깃·플래시 방법을 모름 → 제조사 예제와 board definition부터 확인, 안 되면 멘토에게 타깃 이름과 디버거 연결 질문
2. 디스플레이·진동 모터·배터리 전원을 보드에서 따도 되는지 모름 → 각 부품 전류 스펙과 보드 3.3V 레일 허용 전류 먼저 확인, 부족하면 별도 전원
3. S25와 BLE 연결이 안정적인지, 결제 요청 크기가 한 번에 전달되는지 모름 → GATT 쓰기·알림을 반복 시험해 연결 끊김 횟수와 전송 크기 측정
