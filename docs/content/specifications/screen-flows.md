# 화면별 동작·상태 명세

전체 기능을 앱 연동까지 12주 안에 완료하는 계획의 화면 초안이다. 화면 ID는 탐색·개발 경계를 정하는 식별자이며 실제 라우트/페이지 수를 확정한 것은 아니다. 담당자·공수 배정은 하지 않는다.

[연결 명세](interface-contracts.md) · [상세 DTO](critical-dtos.md) · [JSON 원본](screen-flows.json)

## 공통 화면 규칙

- 로딩과 데이터 없음, 권한 거절과 서비스 장애를 구분한다. 빈 잔액/목록은 조회 성공 후에만 확정한다.
- 변경 요청에는 같은 의도의 중복 탭을 막는 처리와 서버 멱등성을 함께 적용한다. 버튼 비활성만으로 중복을 방지했다고 보지 않는다.
- 진행 중 화면을 닫는 것은 작업 취소와 다르다. 제출된 거래는 계속 추적하고 다시 열면 식별자로 조회한다.
- 앱의 캐시는 표시를 돕는 자료다. 서명·환불·혜택 사용·반납·권한 변경 전에 원천 상태와 revision을 검사한다.
- 복구를 위한 ID/진행 단계는 보호 저장할 수 있지만 니모닉·private key·일회용 proof를 일반 화면 상태에 직렬화하지 않는다.
- 성공은 실제 실행/대사 상태를 근거로 표시한다. 서명 완료·HTTP 200·파일 전송 완료는 각각 다음 단계가 있을 수 있다.
- 사람에게 보여줄 오류 문구는 원인과 다음 행동을 설명하고 원시 서명·토큰·개인 자료를 노출하지 않는다.

## U01 · 로그인·계정 연결 (user)

- 입력/시작: 제공자 선택·연결할 기존 계정 재인증
- 로딩/처리 중: API-103에서 flow 발급 후 제공자별 SDK/시스템 인증; API-001/002의 providerProof로 교환
- 성공/결과: 사용자와 연결된 제공자 표시
- 빈 상태/실패: 취소는 이전 화면; 계정 충돌은 자동 병합하지 않고 확인 경로
- 닫기/재실행/복구: 앱 재시작 시 flow 유효성·소유 결합 재확인; 불명확한 code 소비·refresh 재사용은 재로그인
- 연결: AUTH-02, AUTH-03, AUTH-04; API API-001, API-002, API-003, API-005, API-006, API-103; BLE 직접 명령 없음

## U02 · 지갑 목록·선택·자산 (user)

- 입력/시작: 개인/점주 컨텍스트·지갑·체인 선택
- 로딩/처리 중: 선택 context/wallet/binding/revision을 유지; 승인 화면은 새 snapshot 요청
- 성공/결과: HW/Cloud/스마트 계정과 네이티브 가스·결제 토큰 분리
- 빈 상태/실패: 연결 지갑 없음은 생성/등록; 조회 실패를 잔액 0으로 표시하지 않음; 승인 version/profile 미지원·권한 부족은 새 승인 차단, 원 기록 유지
- 닫기/재실행/복구: 계정/매장 조회 권한 거절 시 빈잔액으로 위장하지 않고 접근 불가 표시
- 연결: APP-02, MPC-02; API API-007, API-008, API-009, API-014, API-090; BLE 직접 명령 없음

## U03 · 송금 검토·승인·결과 (user)

- 입력/시작: 수취·자산·금액·지갑
- 로딩/처리 중: 개인 API017 생성 또는 지정 signer B의 원 merchant_refund snapshot 조회를 구분→HW BLE/Cloud API015→AC 발급→정확한 제출→부모/체인 조회. 환불을 개인 송금으로 생성하지 않음
- 성공/결과: 실제 실행 결과와 수수료/거래 링크
- 빈 상태/실패: 가스 부족·거절·만료·제출 불명확을 구분; 자동 새 송금 금지; 승인 version/profile 미지원·권한 부족은 새 승인 차단, 원 기록 유지
- 닫기/재실행/복구: 로그아웃/만료/응답 유실 시 원 operation/context와 발급 멱등키로 재인증·대사; 자동 재송금 금지
- 연결: APP-03, PAY-01, PAY-02, MPC-03; API API-015, API-017, API-018, API-019, API-020, API-108, API-109, API-110; BLE wallet.sign.prepare, wallet.sign.result

## O04 · 권한·감사 (ops)

- 입력/시작: 대상·행위자·기간 검색
- 로딩/처리 중: 허용 범위 내 조회
- 성공/결과: 민감값 제외한 변경 기록
- 빈 상태/실패: 조회 권한 거절·보관 범위 밖 안내
- 닫기/재실행/복구: 필터 복원과 재인증; 민감 결과 로컬 캐시 금지
- 연결: OPS-01, RELEASE-02; API API-088; BLE 직접 명령 없음

## D01 · 상태·서명 승인 (device)

- 입력/시작: 기기에서 확인 가능한 가게·자산·수취·금액·가스
- 로딩/처리 중: 인증된 BLE 역할과 전체 snapshot/선택 키/세대 확인 후 물리 승인
- 성공/결과: 일반 서명은 승인한 payload 결과; 반납은 로컬 초기화·서버 ACK·기기 정리 상태를 구분, 로컬 삭제만으로 재대여 완료 표시 금지
- 빈 상태/실패: 미지원 호출·체인·만료·세션 불일치 거절; request.cancel은 실행 허가가 발급된 reset job을 취소하지 않음; 승인 version/profile 미지원·권한 부족은 새 승인 차단, 원 기록 유지
- 닫기/재실행/복구: HTTP token 저장/계정 로그인 요구 없음; 기한/미지원 profile 차단, 이미 생성된 서명 상태 보존
- 연결: HW-05, HW-07, STAMP-04; API 직접 호출 없음; BLE payment.prepare, payment.result, wallet.sign.prepare, wallet.sign.result, request.cancel, device.reset.prepare, device.reset.confirm
- 반납 상세 후보: [상태·문구·복구 동작](return-screen-design.md). 후보 프로토콜의 제품 구현은 미완료.

## D02 · 녹음·찾기·스탬프·업데이트 상태 (device)

- 입력/시작: 버튼·인증된 명령
- 로딩/처리 중: 기능별 표시와 자원 중재
- 성공/결과: 녹음/찾기/혜택/버전 상태
- 빈 상태/실패: 동시 요청 우선순위·끊김·복구 필요
- 닫기/재실행/복구: 부팅 상태 조회; 지갑 승인 화면과 녹음 표시 혼동 금지
- 연결: REC-01, FIND-01, STAMP-02, OTA-03, HW-07; API 직접 호출 없음; BLE recording.start, recording.stop, find.start, passport.sync, fota.status
