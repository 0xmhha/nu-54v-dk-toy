# P02 요구사항 명세 — 대여자 폰 앱

[DF-20260925-02](../../planning/design-freeze-checkpoint-02.md) 기준 P02 폰 앱이 만족해야 하는 요구를 정한다. 메시지와 필드는 [payment-protocol.md](../../specifications/protocol/payment-protocol.md)와 스키마를 따른다.

## 1. 용어

- **본딩한 링크:** 기기와 LE Secure Connections로 페어링하고 키를 저장한 BLE 링크. 키 없는 기기는 Just Works 본딩, 셋업한 기기는 Passkey Entry 본딩만 본딩한 링크로 인정한다 [N27].
- **재연결 코드:** 폰 앱이 셋업 때 정해 기기에 기록하고 한 번 보여 주는 6자리 passkey. 다른 폰과 본딩할 때 쓴다.
- **확인 필드:** 기기가 서명하려는 값 중 대여자에게 보여 줄 가맹점 이름, orderId, token, payout, amount. `confirm.show`로 받는다 [N26].

## 2. 기능 요구사항

| ID | 요구 | 시험 | 수용 |
|---|---|---|---|
| P02-FR-01 | 페어링 모드의 기기(서비스 UUID와 LE Limited Discoverable 플래그)를 스캔해 목록으로 보이고, 대여자가 고른 기기와 본딩한다. 키 없는 기기는 Just Works와 기기 버튼 확인, 셋업한 기기는 재연결 코드(passkey)로 Passkey Entry 본딩을 한다 [N27] | 본딩 로그 | W12-01 |
| P02-FR-02 | `confirm.show`와 결과 메시지는 본딩한 링크에서 받은 것만 처리한다 [N26][N27] | 본딩하지 않은 링크 주입 시험 | W12-01 |
| P02-FR-03 | 확인 화면은 `confirm.show`의 값만 표시하고, 키오스크나 다른 출처의 값을 섞지 않는다 [N26] | 화면 캡처와 서명 필드 비교 | W12-02 |
| P02-FR-04 | 주소는 EIP-55 체크섬 형태로, amount는 토큰 단위로 소수점 둘째 자리까지 표시하고 셋째 자리 이하는 버린다(예: 5.009999 USDC는 5.00 USDC) [N31]. 토큰 표에 없는 token은 base unit 정수와 주소를 그대로 표시한다 | 벡터 기반 표시 시험 | W12-02 |
| P02-FR-05 | 앱에는 승인 버튼이 없고, 화면에 "기기 버튼을 눌러 승인하세요"를 안내한다 [N26] | 화면 검토 | W12-02 |
| P02-FR-06 | PIN은 입력받지 않는다. PIN 입력이 필요한 순간에는 기기 버튼과 LED로 입력하라고 안내한다 [N28] | 화면 검토 | W12-12 |
| P02-FR-07 | `payment.outcome`에 해당하는 최종 결과(approved, refused, failed, Checking)를 기기에서 전달받아 표시한다 | 결과별 화면 캡처 | W12-03 |
| P02-FR-08 | 결제 모드를 켜고 끄는 설정을 제공한다. 결제 모드에서만 기기가 결제용 광고를 한다 [N27] | 광고 유무 확인 | W12-01 |
| P02-FR-09 | 단계별 상태 머신으로 동작한다. 등록한 기기가 없으면 스캔부터, 있으면 저장된 본딩으로 다시 연결하고 `device.info`로 기기 상태와 지갑 주소를 확인한 뒤 홈으로 간다. 기기가 초기화되었으면 지갑 설정부터, 지갑 주소가 다르면 기기를 지우도록 안내한다 | jest 상태 전이 시험 | W12-01 |
| P02-FR-10 | 키 없는 기기에 대여 셋업 1, 2단계를 보낸다: `setup.operator`(배포 기록의 운영자, 컨트랙트, chainId, 앱이 난수로 정한 passkey), 기기 버튼 승인, 기기 버튼 PIN. 키는 기기 TRNG로만 만들어지고 앱에는 니모닉이나 키가 없다 [N11][N23]. keygen 뒤 passkey를 재연결 코드로 한 번 보이고 저장하지 않으며, 기존 본딩을 지우고 그 코드로 다시 본딩한다 [N27] | jest(software device), 실기 | W12-01 |
| P02-FR-11 | `wallet.check`로 32바이트 난수 challenge에 대한 WalletCheck 서명을 받아, 복원한 서명자가 keygen(또는 `device.info`) 주소와 같을 때만 기기를 등록한다 [N04] | jest(다른 키 서명 거절), 실기 | W12-01 |
| P02-FR-12 | 등록된 기기 목록(BLE 주소, 이름, 지갑 주소)을 보이고, 지우면 폰의 본딩과 기록을 함께 지운다. 시스템이 본딩 해제를 거절하면 블루투스 설정에서 지우도록 안내한다 | jest, 실기 | W12-01 |

## 3. 비기능 요구사항

| ID | 요구 | 시험 |
|---|---|---|
| P02-NFR-01 | `confirm.show` 수신부터 화면 표시까지 300 ms 안 | 로그 타임스탬프 |
| P02-NFR-02 | 로그와 화면에는 줄인 주소·해시만 남긴다. 확인 화면의 payout은 대여자가 대조할 수 있도록 전체 주소를 보여 주되 로그에는 줄여 남긴다 [N16] | 로그 샘플 검토 |
| P02-NFR-03 | 앱은 개인 키, 니모닉, PIN을 저장하지 않는다 [N28] | 저장소 덤프 검토 |

## 4. 인터페이스

- **P01 기기:** 본딩한 링크의 결제 GATT 서비스. 기기→앱 `confirm.show`, 결과 전달. 조각과 envelope 규칙은 프로토콜 4절을 따른다.
- **P05 운영 도구:** 기기 라벨 QR 형식(BLE 주소, passkey)을 정한다.
