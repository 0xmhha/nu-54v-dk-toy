# P02 기획 — 대여자 폰 앱

이 문서는 DF-20260925-02 기준으로 P02 대여자 폰 앱이 이번 12주 사이클에서 무엇을 만들고 무엇으로 완료를 판정하는지 정한다 [N01]. P02는 2026-09-28 개정에서 이번 사이클 제품으로 올라왔다 [N26]. 규칙과 값은 [DF-20260925-02](../../planning/design-freeze-checkpoint-02.md)와 [결제 프로토콜](../../specifications/protocol/payment-protocol.md)을 따르고, 이 문서는 결정 ID로만 인용한다.

## 1. 목표

기기(P01)에는 화면이 없다. 대여자 본인의 Android 폰에서 동작하는 React Native 앱이 기기와 본딩해 기기를 설정하고, 결제할 때마다 기기가 보낸 결제 필드를 보여 주는 확인 화면이 된다 [N26]. 승인은 기기 버튼으로만 하고, 앱에는 승인 버튼이 없다. 앱은 키를 갖지 않고 서명하지 않는다.

## 2. 범위

| 영역 | 이번 사이클에 만드는 것 |
|---|---|
| 본딩 | 기기 라벨 QR(BLE 주소와 기기별 passkey)을 읽어 LE Secure Connections Passkey Entry로 본딩 [N27] |
| 결제 확인 | `confirm.show`로 받은 가맹점 이름, orderId, token, payout, amount 표시와 최종 결과 표시 [N26] |
| 기기 설정 | 결제 모드 켜기, 연결 상태, 한도 표시. PIN은 기기 버튼으로 입력하므로 앱은 안내만 한다 [N28] |
| 공유 코드 | 조각 처리와 CBOR codec을 키오스크와 공유(`packages/protocol/ts`) |

## 3. 일정

| WBS | 작업 | 주차 |
|---|---|---|
| WBS2-P02-01 | 앱 골격, BLE 모듈, QR 읽기, Passkey Entry 본딩 | W10–W11 |
| WBS2-P02-02 | 기기 설정 화면 | W11 |
| WBS2-P02-03 | `confirm.show` 결제 확인 화면 | W12 |
| WBS2-P02-04 | 폰과 키오스크 동시 연결 결제 시험 | W12 |

담당은 role A(펌웨어 담당)다 [N15]. role A의 W8–W12 부하는 가용 일수를 넘고 담당자가 이를 감수했다 [N30].

## 4. 의존성

| 필요한 것 | 제공 | 시점 |
|---|---|---|
| 기기별 passkey 기록과 라벨 | P01 WBS2-P01-12, P05 WBS2-P05-05 | W8 |
| `confirm.show` 전송 | P01 WBS2-P01-13 | W10 |
| 키오스크 결제 세션 | P04 | W7 이후 |

## 5. 위험

- 결제 확인 화면이 W12에 끝나므로 W11–W12 리허설의 앞부분은 폰 확인 화면 없이 진행한다. W12-02(표시)는 WBS2-P02-03 이후에 기록한다.
- 대여자 폰이 뚫리면 표시를 믿을 수 없다. 기기 버튼 승인과 컨트랙트 한도가 손실을 제한한다 [N26].
- 기기가 폰과 키오스크를 동시에 연결해야 한다. 두 연결의 MTU와 연결 간격이 서로 영향을 줄 수 있어 WBS2-P02-04에서 확인한다.

## 6. 범위 밖

- 결제 승인 버튼
