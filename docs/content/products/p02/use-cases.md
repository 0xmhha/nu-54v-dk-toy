# P02 유즈케이스 — 대여자 폰 앱

[DF-20260925-02](../../planning/design-freeze-checkpoint-02.md) 기준 P02 폰 앱의 사용 흐름이다. 요구는 [srs.md](srs.md)를 따른다.

## 1. 행위자

| 행위자 | 역할 |
|---|---|
| 대여자 | 자기 폰에 앱을 설치하고 대여한 기기와 본딩한다. 결제 때 앱 화면을 보고 기기 버튼으로 승인한다 [N26] |
| 기기(P01) | 본딩한 앱에 확인 필드와 결과를 보낸다 |
| 키오스크(P04) | 기기와 결제 세션을 연다. 앱과 직접 통신하지 않는다 |

## 2. UC-P02-01 기기 본딩

- **사전 조건:** 운영 도구가 대여 셋업에서 기기별 passkey를 기록하고 라벨 QR을 인쇄했다 [N27].
- **주 흐름:**
  1. 대여자가 앱에서 "기기 연결"을 누르고 라벨 QR을 읽는다.
  2. 대여자가 기기 버튼을 길게 눌러 페어링 모드에 들어간다. LED가 페어링 모드를 알린다.
  3. 앱이 QR의 BLE 주소로 연결하고 QR의 passkey로 Passkey Entry 본딩을 마친다.
  4. 앱이 연결 상태와 기기 상태를 보여 준다.
- **예외 흐름:** passkey가 틀리면 본딩이 실패하고 앱이 QR을 다시 읽으라고 안내한다. 페어링 모드가 아니면 기기가 새 본딩을 받지 않는다.
- **요구:** P02-FR-01

## 3. UC-P02-02 결제 확인

- **사전 조건:** 앱이 본딩한 링크로 연결되어 있고 결제 모드가 켜져 있다.
- **주 흐름:**
  1. 키오스크가 기기와 결제 세션을 열고 주문을 보낸다.
  2. 기기가 검사를 통과한 뒤 `confirm.show`를 앱에 보낸다 [N26].
  3. 앱이 가맹점 이름, 금액(토큰 기호와 소수 자릿수 적용), payout, orderId를 표시하고 "기기 버튼을 눌러 승인하세요"를 안내한다.
  4. 대여자가 가맹점과 금액을 확인하고 기기 승인 버튼을 누른다.
  5. 기기가 결과를 앱에 전달하고 앱이 approved를 표시한다.
- **대안 흐름:** 대여자가 거절 버튼을 누르면 기기가 `USER_REJECTED`로 거절하고 앱이 refused를 표시한다.
- **예외 흐름:** 앱 연결이 끊겨 있으면 릴리스 빌드의 기기는 `NOT_PERMITTED`로 결제를 거절한다.
- **요구:** P02-FR-02, P02-FR-03, P02-FR-04, P02-FR-05, P02-FR-07

## 4. UC-P02-03 PIN이 필요한 순간

- **주 흐름:** 셋업이나 한도 변경에서 PIN이 필요하면 앱은 "기기 버튼으로 PIN을 입력하세요"만 안내한다. 대여자는 LED 안내에 따라 기기 버튼으로 입력한다 [N28].
- **요구:** P02-FR-06
