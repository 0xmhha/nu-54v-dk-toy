# P07 유즈케이스 — 최소 PaymentSettled indexer

P07의 행위자는 키오스크(P04)와 운영자(시험 담당)다. 요구 번호는 [SRS](srs.md)를 가리킨다. 근거 결정은 [N19]다.

## 1. UC-P07-01 영수증 조회

| 항목 | 내용 |
|---|---|
| 행위자 | 키오스크 |
| 사전 조건 | 결제가 finalized PaymentSettled로 approved 된 상태 [N08] |
| 기본 흐름 | 1. 키오스크가 approved 화면에서 영수증 보기를 누른다. 2. `GET /receipts/{merchant}/{orderId}`를 호출한다. 3. P07이 영수증을 돌려준다. 4. 키오스크가 블록 번호·시간·줄인 tx hash를 표시한다 |
| 예외 흐름 | 3a. 아직 ingest 전이면 404 → 키오스크는 "영수증 준비 중"을 표시하고 결제 결과는 그대로 둔다. 3b. P07이 응답하지 않으면 키오스크는 체인 이벤트로 확인한 결과만 표시한다 |
| 사후 조건 | 결제 상태는 바뀌지 않는다 |
| 요구 | P07-FR-04, P07-FR-06 |

## 2. UC-P07-02 이벤트 수집

| 항목 | 내용 |
|---|---|
| 행위자 | P07 ingest 프로세스(시스템) |
| 사전 조건 | 정산 컨트랙트 주소와 시작 블록이 설정되어 있음 |
| 기본 흐름 | 1. finalized 블록 번호를 읽는다. 2. cursor+1부터 그 블록까지 PaymentSettled 로그(전체 시그니처의 topic0)를 읽는다 [N08]. 3. `(txHash, logIndex)` 기준으로 저장한다. 4. cursor를 옮긴다 |
| 예외 흐름 | 2a. RPC 오류 → cursor를 유지하고 다음 주기에 다시 읽는다. 3a. 이미 있는 로그 → 건너뛴다 |
| 사후 조건 | cursor 이하 모든 PaymentSettled가 저장됨 |
| 요구 | P07-FR-01, P07-FR-02, P07-FR-03 |

## 3. UC-P07-03 재시작 후 이어 읽기

| 항목 | 내용 |
|---|---|
| 행위자 | 운영자 |
| 사전 조건 | ingest 중 프로세스가 종료됨 |
| 기본 흐름 | 1. 운영자가 프로세스를 다시 시작한다. 2. P07이 저장된 cursor를 읽는다. 3. 그 다음 블록부터 UC-P07-02를 계속한다 |
| 확인 | 종료 전후 로그 수를 체인의 `eth_getLogs` 결과와 비교해 같음 |
| 요구 | P07-FR-02, P07-NFR-02 |

## 4. UC-P07-04 P07이 컷된 경우

| 항목 | 내용 |
