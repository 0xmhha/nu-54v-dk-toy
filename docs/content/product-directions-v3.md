# 게임·피규어·생활 속 놀이 — 세 번째 제품 제안

2026-09-14. 이전 추천의 AI 작업 다이얼은 사용자 취향에 맞지 않아 우선순위에서 제외한다. 현재 관심은 게임·영상·소파 생활 또는 외출 중 기록이며, PC 작업 도구는 게임 컨트롤러 외에는 선호하지 않는다. 아래는 선택 전 제품 아이디어다.

## NU-54V DK를 BLE 조이스틱으로 쓸 수 있는가

가능한 구현 방향은 BLE의 HID over GATT로 축과 버튼 정보를 전달하는 것이다. [Bluetooth SIG의 HOGP](https://www.bluetooth.com/specifications/specs/hid-over-gatt-profile-1-0/)가 BLE HID 경로를 정의하고, [Zephyr HID Peripheral 예제](https://docs.zephyrproject.org/latest/samples/bluetooth/peripheral_hids/README.html)는 HID GATT 서비스를 구현한다. 예제는 마우스이므로 게임패드용 Report Map, 입력 리포트, 버튼·아날로그 센서 읽기, 보드 설정을 작성해야 한다. 실물 NU-54V DK에서 이번 대화 중 검증한 것은 아니다.

경로는 `스틱·버튼 → NU-54V DK → BLE HID → PC → 게임`이다. 일반 HID 게임패드가 XInput 컨트롤러가 되는 것은 아니다. [Microsoft의 비교 문서](https://learn.microsoft.com/en-us/windows/win32/xinput/xinput-and-directinput)는 XInput 전용 게임과 DirectInput 장치 사이의 차이를 설명한다. [Steam Input](https://partner.steamgames.com/doc/features/steam_controller/device)은 DirectInput 게임패드를 지원하므로 Windows에서 일반 게임패드로 인식되는 경로를 만든 뒤 우선 검증할 후보지만, 특정 자작 BLE 장치의 인식·매핑·게임별 동작을 보장하지 않는다.

모든 PC 운영체제, 모든 Steam 게임, Xbox식 진동 출력까지 한꺼번에 지원하는 목표는 잡지 않는다. 특히 게임 상태를 읽어 LED나 서보로 돌려주는 것은 입력과 별개의 기능이다. 게임의 공식 API·텔레메트리 또는 별도로 작성한 연동이 필요하다.

### 제작 결정을 위한 첫 1~2주의 관문

1. 보드의 실제 리비전·SDK·디버거로 기본 BLE 예제를 실행한다.
2. 한 개의 2축 스틱과 버튼 2개로 최소 HID 게임패드를 만든다.
3. 대상 PC에서 페어링·축 범위·중립점·재연결을 확인한다. Windows를 쓴다면 게임 컨트롤러 설정에서도 본다.
4. 사용자가 실제로 즐기는 게임 하나에서 Steam Input 매핑을 시험한다.
5. 30분 플레이에서 입력 누락·중립점 흔들림·체감 지연을 기록한다. BLE PHY 속도를 게임의 입력 지연으로 취급하지 않는다.

이 관문 전에는 최종 케이스나 모터에 큰 비용을 쓰지 않는다. 실패하면 원인을 HID 인식·Steam 매핑·게임 입력 방식 중 어디에 있는지 나눠 확인한다. 추가 USB 수신기를 쓰는 대안은 호환성에 따라 검토할 수 있지만 별도 보드와 펌웨어 비용이 생긴다.

## A. CORE-01 — 컨트롤러가 피규어의 심장이 된다

**장면:** 소파에서는 양손 스틱이 있는 무선 컨트롤러로 게임을 한다. 게임을 끝내고 표시창이 달린 전자 코어를 빼서 책상 위 메카닉 피규어에 꽂으면 눈과 가슴에 불이 들어온다. 피규어는 그날의 플레이 기록에 따라 정해진 표정을 보여주고, 버튼을 누르면 짧은 조종사 일지를 들려준다.

핵심은 전자 코어 1개에 직접 출력한 외장 2개를 만드는 것이다. 컨트롤러의 그립·스틱·버튼은 플레이를 위해, 피규어 외장은 전시와 반응을 위해 설계한다. 두 외장을 만드는 이유가 일상 사용의 전환에 있다.

- NU-54V DK: 아날로그 스틱·버튼 읽기, BLE HID, 표시, LED, 외장 식별.
- 센서: 스틱의 위치 센서, 코어 장착 감지용 스위치 또는 Hall 센서. IMU는 필수 아님.
- PC: 실제 게임 실행, 명시적 세션 시작·종료 및 간단한 기록 저장, 필요시 LLM 호출.
- LLM: 플레이 후 사용자가 남긴 짧은 메모와 수집 가능한 기록을 ‘메카닉의 조종사 일지’로 표현한다. 게임의 승패·킬 수를 모든 게임에서 자동 추출한다고 가정하지 않는다.
- 오프라인: 컨트롤러 기본 입력과 피규어의 사전 제작된 표정·조명은 모델 없이 동작한다.

**12주 필수:** BLE 컨트롤러 1종, 대상 게임 1개, 코어와 교체 외장 2개, 피규어 LED·표정, PC에서 요청하는 짧은 일지. 배터리는 전원·충전 설계가 준비된 뒤 통합하며 최초 검증은 USB 전원으로 한다.

**선택 확장:** 고개 움직임 서보 1개, 게임 상태 기반 피규어 반응, 단순 육성 상태. 완전한 다마고치·걷는 로봇·음성 대화·범용 게임 텔레메트리를 필수 범위에 함께 넣지 않는다.

**장점:** 실제 게임 컨트롤러가 남고, 프라모델 외형을 설계·교체하는 재미가 이어진다. **약점:** 일반 패드보다 저렴하거나 인체공학적으로 뛰어날지는 미정이며, 교체 코어의 접점·고정 구조가 추가 난관이다. DK가 들어가는 실측 크기로 설계하고 작은 가슴 안에 들어간다고 미리 가정하지 않는다.

대략 일정: 1~2주 HID 검증 → 3~5주 스틱·버튼·입력 보정 → 6~8주 컨트롤러 외장·사용 시험 → 9~10주 피규어 외장·LED·장착 감지 → 11~12주 일지 기능·신뢰성·전시.

## B. Memory Familiar — 내 하루를 먹고 자라는 동행 기기

**장면:** 외출 중 기억하고 싶은 순간에 버튼을 누르고 ‘처음 들어간 골목에서 좋은 빵집을 찾았다’고 짧게 말한다. 귀가 후 PC에 동기화하면, 기기 속 작은 탐험가가 그 기억으로 아이템을 얻고 하루의 모험 일지를 만든다. 일주일 뒤 화면에서 이번 주에 모은 물건을 훑어보면 실제 추억과 원문 메모를 다시 볼 수 있다.

다마고치의 성장을 개인 음성 일기와 연결한다. 굶거나 접속하지 않았다고 벌주는 시스템 대신, 사용자가 남긴 기록만큼 컬렉션이 늘어나는 구조다.

- NU-54V DK: 버튼·마이크·시간·움직임 이벤트 수집, 외부 저장, 작은 화면의 사전 제작된 캐릭터와 간단한 상태 관리.
- 센서: PDM 마이크가 핵심. IMU는 들어 올리기·흔들기 상호작용에 선택적으로 사용한다.
- PC: 녹음 전송, 음성 인식, LLM을 통한 일기·아이템 설명 생성.
- LLM: 사용자의 원문을 읽고 판타지 표현을 제안한다. 실제 일기와 꾸며낸 모험 문장을 분리해 저장한다.
- 규칙: 성장 수치와 보상 지급은 코드가 결정한다. LLM이 임의로 게임 데이터를 바꾸지 않는다.

**12주 필수:** 30~60초 개인 메모, 외부 저장, 귀가 후 PC 동기화, 캐릭터 1종, 미리 만든 아이템 10종, 주간 기록 화면. 장소는 사용자의 음성에서 받으며 GPS·실내 위치 추정·센서만으로 장소 파악은 하지 않는다. 스마트폰 앱과 상시 인터넷 없이도 녹음은 가능하게 계획한다.

**장점:** 외출 후 실제 개인 기록이 남고 캐릭터를 소유하는 재미가 있다. **약점:** 녹음·저장·전송·음성 인식을 모두 다뤄야 하며, DK 기반 1차 제품을 작은 열쇠고리 크기로 만들기는 어렵다. 손바닥 크기 또는 더 큰 휴대 장치를 예상하고 실측한다.

16kHz·16bit·모노 녹음은 분당 약 1.92MB이므로 외부 저장이 필요하다. 새로운 지역이나 친구를 자동 인식한다고 표현하지 않는다.

## C. Dungeon Relic — 집 한 칸을 던전으로 바꾸는 실물 유물

**장면:** 방 안 사물 몇 곳에 태그를 붙인다. 손에 든 유물형 장치가 진동하고 화면에 단서가 나타난다. 태그에 장치를 대면 문이 열리고, 다이얼로 암호를 맞추거나 기울여 퍼즐을 푼다. 다음 날에는 같은 장소를 다른 등장인물과 이야기로 탐험한다.

이 제품은 간단한 방탈출 게임을 실제 소품과 연결한다. LLM은 세계관·대사·힌트를 쓰고, 아이템·열쇠·승리 조건은 검증된 규칙으로 처리한다. 기기의 화면·불빛·진동이 사건을 전달한다.

- NU-54V DK: IMU·다이얼·버튼·태그 리더 입력, 화면·LED·진동, PC와 BLE 통신.
- NFC: nRF54L15의 내장 NFC를 태그 리더로 착각하면 안 된다. 물체의 태그를 읽으려면 **외부 NFC 리더 모듈**을 추가한다. 초기에는 버튼·Hall 센서 소품으로 더 단순하게 시작할 수 있다.
- PC: 한 방 내 BLE 연결로 시나리오 생성과 판정 처리. 인터넷 없이 플레이할 고정 시나리오도 하나 둔다.

**12주 필수:** 장치 1대, 태그 3개, 고정 퍼즐 3종, 검증 가능한 퀘스트 구조 1개, LLM 대사·힌트 변형. BLE 수신 세기로 정확한 보물 방향을 찾거나 집 전체 위치를 추적한다고 주장하지 않는다. 가까이 가져가서 인식하는 방식이다.

**장점:** 다른 사람에게 ‘한번 해보라’고 보여주기 좋고, 피규어·소품 외형을 만들 이유가 분명하다. **약점:** 일상 편의보다는 반복해서 놀 만큼 콘텐츠를 잘 만드는 것이 중요하다. 혼자·둘이·손님과 하는 놀이 중 하나를 주 사용 장면으로 정해야 한다.

## D. Tiny Cockpit — 무릎 위에 올라오는 나만의 조종석

**장면:** 큰 스틱, 짧은 스로틀, 커버를 열고 누르는 시동 버튼, 몇 개의 토글 스위치가 있는 소형 콘솔을 무릎에 올린다. 자동차·우주선·로봇 등 좋아하는 게임에 맞춰 조작부를 배치하고, 실제로 레버와 스위치를 조작하며 플레이한다.

범용 패드를 저렴하게 복제하기보다 게임 한 종류에 맞춘 조작감을 만드는 제품이다. 원하는 조작에 따라 Hall 센서 스틱·슬라이더·로터리 엔코더를 고르고 NU-54V DK가 BLE HID로 전달한다.

**12주 필수:** 스틱 1개, 스로틀 1개, 버튼·스위치 6~8개, 케이스, 게임별 매핑 1종. 센서 수와 핀 배치에 맞춰 스위치 매트릭스나 외부 ADC 필요 여부를 확인한다. 포스 피드백은 필수에서 제외한다.

LLM은 선택적으로 플레이 후 기록을 정리하거나 게임 매뉴얼을 찾아 설명하는 무전 담당 역할을 줄 수 있다. 빠른 조작 경로에는 넣지 않는다. 게임 상태에 따라 자동으로 말하게 하려면 그 상태 데이터를 읽는 연동이 먼저 필요하다. 예를 들어 [SCS의 Telemetry SDK](https://modding.scssoft.com/wiki/Documentation/Engine/SDK/Telemetry)는 차량 데이터를 외부 프로그램에 제공하는 공식 경로다. 이것이 다른 게임의 범용 API는 아니다.

**장점:** 이미 좋아하는 게임이 있다면 완성 후 사용할 이유가 가장 확실하다. **약점:** 게임 취향을 모르고 만들면 크고 불편한 장난감이 되기 쉽다. 원래 즐기는 장르가 레이싱인지·비행인지·액션인지부터 선택해야 한다.

## 추천 판단

게임과 프라모델 취향을 한 제품으로 연결하려면 **CORE-01**을 가장 먼저 검토한다. LLM이 제품의 핵심 의미를 만들어야 한다면 **Memory Familiar**, 독특한 놀이 경험이 우선이면 **Dungeon Relic**이 더 맞다. **Tiny Cockpit**은 좋아하는 시뮬레이션 게임이 있을 때 가장 실용적이다.

정식 기획서·Medium 글·최종 예상 이미지는 사용자가 끌리는 제품을 선택한 뒤 교체한다. 현재는 제품이 확정되지 않았으므로 기존 초안을 새 이름으로 바꿔 발행하지 않는다.
