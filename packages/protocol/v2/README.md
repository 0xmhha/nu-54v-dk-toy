# Wire v2 and merchant quote

The pilot profile accepts chain 8283 and escrow payment. An authenticated release profile supplies the exact v2 contract and asset addresses. Direct payment has a distinct signed mode reserved for a later profile. The two pilot entry paths are a kiosk-selected customer and a private phone order. An order resumed through either path has the same bytes, digest and registered merchant signature. The path identifier belongs to the authenticated session.

## Encoding

The unsigned representation contains 21 consecutive 32-byte words. It begins with the EIP-712 domain words, `chainId` and `verifyingContract`, followed by the 19 `MerchantQuote` fields in schema order. The signed representation appends exactly 65 bytes, canonical secp256k1 `r || s || v`. All numeric fields are unsigned big-endian, zero-padded on the left. Addresses are 20 bytes, zero-padded to 32. A `bytes32` field occupies the entire word. The representation has no variable-sized fields, text, trailing bytes, or ABI tuple offset. The canonical EIP-712 type string is `MerchantQuote(type field,...)` in schema order without spaces after commas.

The digest is `keccak256(0x1901 || domainSeparator || hashStruct)`. EIP-712 domain name is `NU54 Payment Settlement` and domain version is `2`. Domain separator and quote struct hash follow EIP-712. Domain and struct hashes use Keccak-256. The signer is an EVM address recovered from the confirmed digest. Signature scalars satisfy `0 < r < n` and `0 < s <= n/2`. The only recovery bytes are 27 and 28. A valid shape carries no authority by itself.

Every field is nonzero. Reserved high bits in addresses, uint64 fields and uint8 fields are zero. `amount` stays in exact token minor units. P05 generates `quoteId` and `orderId` independently with a CSPRNG. `merchantId` is the registered public identifier. `claimCommitment` binds the winning session, `intentCommitment` binds order content and pricing, and `payerGeneration` fences the active slot or account authority. A direct-mode renter quote is invalid. Both `issuedAt` and `expiresAt` are UTC Unix seconds. The quote is useful only for `issuedAt <= now < expiresAt`, with a positive duration. On-chain acceptance uses inclusion time. Later finality may confirm an already-included payment.

## Trust boundary

The authenticated caller provides the locally expected unsigned quote, registered merchant signer address, trusted current time, and whether the nonce or order is already consumed. The expected quote comes from the authenticated order/payer authorization and registered deployment/beneficiary state. Copying these inputs from the received raw envelope invalidates the caller's trust boundary. Role and generation are part of the bound expected quote. Verification compares the complete unsigned bytes, checks the pilot profile and time, recovers the signer, then checks the consumed status. Error precedence is malformed, unsupported profile, wrong binding, expired, untrusted signer, consumed. A missing or malformed policy returns `malformed`. Its expected bytes must be a canonical unsigned quote and the independent signer must be a nonzero 20-byte address. The clock is an unsigned 64-bit integer. The TypeScript entry point requires `bigint` and Python requires an exact `int`. Both require a Boolean consumption decision and reject missing values or numeric coercion. Encoding and digest computation are deliberately pure and may represent data for a later supported deployment.

Verification is read-only. P05/P06 own atomic order/nonce consumption. C2 receivers bind fragment sequence, message, direction and version to their authenticated session. Roles get only their declared commands. Reconnect re-establishes the same versioned role, generation and order binding. The v1 rental path remains on its own protocol and EIP-712 v1 domain.

## Public calldata and private order context

Treat the complete signed envelope and all 21 words as public. This includes chain and contract, the registered merchant identifier, payer/asset/beneficiary addresses, exact amount, nonce, versions, authority generation, times, role and mode. Use independent random quote and chain order identifiers. Keep the mappings to the P05 sale, tenant and branch in the restricted P05 database. Public values confer no authority to query an order, claim a session, or retrieve a receipt.

`tenantCommitment`, `branchCommitment`, `claimCommitment` and `intentCommitment` expose only keyed per-quote commitments. P05 derives them using the SDK Go `CommitPrivateContext` function and an independent secret 32-byte CSPRNG key from its protected credential store. The exact HMAC-SHA-256 input is ASCII `NU54-QUOTE-COMMIT-V2` followed by a zero byte, a purpose byte, the 32-byte quote ID, the 4-byte big-endian length, and the purpose-specific value. Purpose bytes are 1 for tenant (16-byte DB UUID), 2 for branch (16-byte DB UUID), 3 for claim (32-byte authorized private claim), and 4 for intent (1–65535 bytes of the issuer's versioned canonical order intent, including pricing). Use identical recorded canonical bytes to recompute a pending quote. Keep the key and private inputs inside P05. Access tokens, customer aliases, receipt locators, internal reservation references, GPS/location and free text never enter the public envelope. The SDK rejects zero values and invalid purpose widths in the commitment API.

P01 compares commitments from the authenticated order context with the signed quote before confirmation. P06 checks the registered merchant's v2 signature over those same commitment words without reading or opening them. Payment acceptance checks the registered asset, beneficiary and beneficiary version, key version, payer authority, inclusion time and atomic order/nonce consumption. P05 preserves the issuer mapping to reconcile a finalized public event with an authorized order and independently authenticate private order queries.
