# Firmware preparation power evidence

The NU-54DK-C electrical reference routes BQ25186 `/PG` through SB2 to P2.08 and exposes `VBAT_MON` through SB4 to P1.12/AIN5. The maintained secure and nonsecure board descriptions declare those inputs. USB `VBUS` and `VEXT` can also feed the system rail through the board's diode paths. These facts describe the board design. They do not identify a particular specimen's populated bridges or prove uninterrupted power during a flash write. [Board reference](../../../products/p10-platform/release/board-reference.json).

The experimental read adapter observes the charger's VIN condition on a qualified board revision and closed SB2 build profile. The TI BQ25186 data sheet defines `STAT0` (0x00) bit 0 as `VIN_PGOOD_STAT` and `VBAT_CTRL` (0x03) bit 7 as `PG_MODE`. The open-drain pin reflects VIN only in PG mode. The adapter performs only register-addressed reads of these two registers and reads the existing active-low GPIO. It never writes a charger register, changes charge settings, drives `/CE`, or reads the clear-on-read fault registers. [TI BQ25186 data sheet](https://www.ti.com/lit/ds/symlink/bq25186.pdf).

Read the mode and reported VIN condition before and after sampling `/PG`. A GPIO/register discrepancy, a change during the sample, GPO mode, an unavailable bus/GPIO, or an unqualified or unsupported bridge profile yields unknown. Consistent success establishes the PMIC's VIN-good condition at observation time. Consistent negative reports only that the PMIC does not qualify VIN. A static deasserted open-drain pin cannot establish continuity by itself. Qualification therefore requires a separate bridge and specimen check; a released default has no qualified input provider and remains unknown.

Owner-management operation 120 (`0x78`) reads this observation without changing operation 119. Its request consists of `0x78` followed by the current nonzero owner generation as a big-endian `u64`. The 43-byte response has operation `0x78`, format byte 1, a status byte (0 unknown, 1 not good, 2 good), the exact owner generation, and the 32-byte registered board identity digest. Authorization, peer and generation are checked again before publication. An unsupported implementation may close the idle probe and a default or unqualified adapter returns unknown. It does not imply that the MCU is powered from VIN, identify USB versus another source, yield battery percentage from voltage, or permit an update. Firmware application still needs a matching verified candidate, trusted update power criteria and an available exclusive physical update path. Those facts must be checked by their own sources at the point of application.

The update-preparation screen keeps the running-image read and the input-power read separate. Verifying a device or reading its running image sends no power probe. The enrolled owner chooses **PMIC input check** explicitly after selecting the authenticated board. The phone clears the displayed value on a failed read, owner scope change or loss of the activity view. It keeps the device-rail state, battery percentage and update permission unconfirmed even when the PMIC reports VIN good.
