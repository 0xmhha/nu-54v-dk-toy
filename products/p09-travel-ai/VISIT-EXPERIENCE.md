# 여행 이용 근거 · 후기 · 스탬프 · 챌린지

- T08은 인증된 P09 이용자에게만 발급 확인된 이용 내역을 보여 준다. 선택한 내역으로 공개 범위와 동의 만료를 확인하고 게시한다. 응답을 받지 못했을 때 다시 제출해도 같은 내용은 기존 결과를 돌려준다. 내용이 다르면 기존 후기를 검토할 수 있다. 시험 후기는 운영 공개 목록의 대상이 아니다.
- T09는 이용 근거의 검증·환불·체인 재구성 상태와 P05 혜택 원장의 실제 반영 상태를 함께 표시한다. 읽기 권한은 발급 근거에 해당하는 최소 결과만 반환한다. 원장 미연결이나 조회 실패는 확인 불가로 표시한다.
- T14는 선택한 이용 내역만 별도 챌린지 동의에 따라 반영하고, 유효한 장소를 중복 없이 최대 3곳까지 센다. 현재 동의·만료·삭제·환불에 따라 진척을 다시 계산한다. 시험·중복 방문은 진척을 추가하지 않는다. 3곳을 채우면 진행 완료만 표시한다.
- 공개 응답은 무작위 후기 ID, 공개 본문, 배지 상태를 반환한다. 취소 또는 정정은 후기 본문 보존과 배지 상태를 개별적으로 처리한다.
- 기존 대상 지정 챌린지 정책은 한 건 선택 흐름을 지원한다. 여러 장소를 반영할 배포는 별도의 활성 챌린지 정책 버전에 `target_required=false`를 설정하고 같은 정책을 P02 등록서에 포함한다. 각 방문 근거는 동의 이후 사용자가 개별 선택한다.

## 실행 경계

P09 마이그레이션 019를 적용하고 기존 후기 암호화 키를 `P09_REVIEW_KEY`에 지정한다. 장소명은 이미 승인된 공개 카탈로그에서 찾는다. 카탈로그 조회에 실패해도 본인 이용 내역은 발급 확인일과 상태로 볼 수 있다.

P05 마이그레이션 040을 적용한다. 기존 `cmd/visit-benefit`은 혜택 지급·회수 효과를 계속 반영한다. 조회는 `cmd/visit-benefit-read`를 별도 내부 TLS 서비스로 실행한다. 서비스는 `P05_BENEFIT_READ_DATABASE_URL`에서 `nu54_p05_benefit_read` 전용 로그인으로 접속하고 `-cert`, `-key`, `-client-ca`, `-reader-sha256`으로 승인된 P09 클라이언트 인증서를 확인한다. P09에는 다음을 지정한다.

- `P09_BENEFIT_STATUS_ENDPOINT`는 내부 HTTPS 서비스의 `/v1/visit-benefits/status`
- `P09_BENEFIT_STATUS_CA`는 P05 서버 인증서를 검증할 CA PEM 파일
- `P09_BENEFIT_STATUS_CERT`, `P09_BENEFIT_STATUS_KEY`는 조회 전용 P09 클라이언트 인증서와 개인키 PEM 파일

P05가 받는 것은 P09가 해당 인증 이용자의 발행 원장에서 조회한 실제 환경의 발급자/근거 쌍이다. 반환하는 것은 현재 지급, 조정, 미반영 개수다. P09는 P05 데이터베이스 자격을 보유하지 않는다. 앱 동작으로 혜택을 지급하거나 조정하지 않는다.

후기와 챌린지에서 선택한 항목의 삭제를 요청하면 해당 항목을 즉시 읽기/진척에서 제외한다. 기존 P09 삭제 워커가 독립 복구 저널에 삭제 표식을 기록한 후 후기 본문 또는 해당 챌린지 반영을 제거한다. 원천 이용 확인은 별도 목적의 발급 원장에 남는다. 챌린지에서 지운 내역은 삭제 이전 동의로 재등록되지 않는다.


앱은 `POST /v1/private/visits`에 `projection: "options"`를 보내 이용 목록을 요청한다. 한 응답에 최대 16건이 포함된다. 장소 상세에서 열면 해당 장소만 조회하고, 스탬프 화면에서만 P05 혜택 원장을 함께 읽는다. 이어보기 커서는 같은 P09 계정과 장소 선택에서만 유효하다. 발급 근거 정정이 이력 순서를 바꾸지 않으며, 각 페이지는 현재 전체 계정의 유효 챌린지 진척을 반환한다. 기존 `GET /v1/private/visits`의 제출 이력과 기존 신청 POST 규약은 유지한다.

## 검증

저장소 루트에서 전용 iOS 시뮬레이터와 새 결과 폴더를 지정한다. PostgreSQL 15의 설치 경로가 다르면 `POSTGRES_BIN`을 설정한다.

```bash
bash scripts/ios/scene-smoke/run-travel-visits.sh <simulator-udid> <derived-data-dir> <new-result-dir>
```

XCTest는 이름이 겹치지 않는 앱 설치본에서 여행자 등록, 후기 게시·앱 재시작·변경 충돌, 같은 결제 근거의 검증 스탬프와 혜택 확정 각 한 건, 같은 근거 다시 반영 및 새로고침의 중복 없음, 실제 P05 원장 조정 읽기, 세 곳 도달·환불·철회, 111건 목록을 넣은 뒤 다음 페이지·같은 페이지 새로고침·이전 페이지를 확인한다. `TravelVisits.xcresult`와 빌드·실행 출력은 지정한 결과 디렉터리에 남는다.

시험기는 임시 Unix 소켓의 로컬 PostgreSQL에 P09와 P05의 별도 데이터베이스를 만들고 각 소유자 마이그레이션을 적용한다. 발급·환불·조정·대량 이력은 테스트 소유자가 합성값으로 주입한다. 실제 앱은 생성한 설치 공개키에 발급된 P09 여행자 인증서만 쓰며, P09와 P05 사이의 mTLS에는 다른 방향의 전용 읽기 인증서를 사용한다. 등록·합성 데이터 조작용 HTTP 진입점은 반복 불가한 시뮬레이터 시험 경로이며 루프백에서만 열고 종료 시 제거한다. 격리된 P05 지급 함수에 같은 합성 결제의 검증을 두 번 전달해 증가가 한 건인지 확인한다. 실제 지급이나 운영 계정은 이 시험에 사용하지 않는다.

독립 P09 본인 권한·커서·과거 기록·삭제 복구 테스트는 각각 비어 있는 P09 workload 및 journal에 소유자 마이그레이션을 먼저 적용한 뒤 실행한다. 테스트 접속 문자열의 DB 이름은 `nu54_p09_`로 시작해야 하고 소켓은 임시 디렉터리 안에 있어야 한다.

```bash
P09_PRIVATE_TEST_DSN='<disposable-workload-dsn>' \
P09_ERASURE_TEST_DSN='<disposable-journal-dsn>' \
go test -count=1 -v ./products/p09-travel-ai/internal/records
```
