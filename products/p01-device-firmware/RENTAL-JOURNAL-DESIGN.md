# O09 대여 세대 보호 저널

새 대여 세대를 활성화할 때 보드가 검증한 지점과 기기 식별자, 64비트 세대, 등록 다이제스트, 실행 측정, 배포 다이제스트, 256비트 체인, 정산 계약, 대여 계정을 보드의 최초 승인 nonce에 결속한다. 기존 v1 대여의 보호 설정에는 이 정보가 없고 기존 settings nonce는 이력을 복원할 수 없다. 기존 등록은 기존 동작과 대사 `unknown`을 유지한다.

## 저장 형식과 승인

RJ03 이미지에는 ASCII 형식 표식, 결속 필드, 256비트 시작·다음 nonce, 항목 수·동결 플래그 및 최초 동결 시각, 고정 순서의 항목 8개를 저장한다. 정수는 부호 없는 big-endian이다. 사용하지 않은 슬롯은 모두 0이다. 항목에는 업무 종류, 상태, 만료, 요청 식별자와 공개 주문 좌표, 최종 EIP-712 승인 다이제스트, 발행한 경우 서명 65바이트를 저장한다. nonce는 시작값에 슬롯 순서를 더한 값이다. 1,814바이트 전체를 원자 교체하는 저장 어댑터가 필요하다. 쉬운 검증을 위해 이 첫 형식이 포화되면 새 승인을 중단하고 이력을 순환 삭제하지 않는다. 상용 세대 활성화 전 실제 보호 저장소 한도와 대여의 예상 승인을 기준으로 용량을 따로 검증한다.

1. 지급은 로컬 버튼이 승인한 가맹점 주소와 원 주문 ID의 조합에 결속한다. 같은 주문 ID를 독립 가맹점에서 사용할 수 있다. 같은 가맹점과 주문의 다른 승인 내용 또는 기한을 거절한다. 한도 변경에는 별도 v1 요청 키가 없어 nonce를 0으로 놓은 타입화 한도 변경 해시를 사용한다. 변경 내용과 만료가 같은 재요청은 같은 한도 승인이다. 각 경로의 기존 기기 세션과 한도 PIN·버튼 확인을 사용한다.
2. 승인 시 보드의 앵커 시간으로 만료를 다시 확인한다. 한 원자 교체로 요청을 예약하고 `next_nonce`를 전진시킨 뒤 서명한다. 원자적으로 발행 상태와 검증된 서명을 저장한 뒤 기존 응답 형식으로 반환한다.
3. 서명 전 폐기나 실패, 재부팅 뒤 남아 있는 예약은 소각으로 종결한다. 모호한 저장 실패는 현재 RAM 사본을 사용 불가로 만들고, 저장소 재조회로 발행이 확인된 경우 동일 서명과 nonce만 회복한다. 누락된 응답, 재시도, 포화로 새 nonce를 중복 발행하지 않는다.
4. 신선한 요청으로 검증된 동결 호출은 대기 확인을 취소하고 영속 동결을 저장한다. 동결 이후 신규 확인과 기존 서명 재응답을 차단한다. 동결 커밋은 공개 RJP1 대사 필드의 Keccak-256이다. 수집기가 증거로 사용하려면 본문을 전용 챌린지와 등록된 보드 인증키에 결속해야 한다.

## 연결 경계

지급·한도 승인과 동결 코어는 같은 구현을 사용한다. 현재 배포의 `setup.operator`와 키 생성 응답은 O09 세대/배포/측정 증거를 제공하지 않는다. 상용 활성화에는 키 생성 직후 첫 승인보다 앞선 인증 등록, 전용 보호 저장소 교체·전원 중단 시험, 측정 및 롤백 방지, 새 세대 초기 승인 차단, 재부팅 시 동결 복원, 인증된 챌린지 응답, 종결 뒤 증거 보존이 필요하다. 이 경계가 연결되기 전 P05의 확정 대사 건수를 활성화하지 않는다. 엄격한 기존 v1 응답 형식은 호스트 공유 벡터를 그대로 사용한다.

## 등록 후보와 저장 어댑터

타입화 등록 후보의 EIP-712 도메인은 기존 v1 체인·정산 계약을 사용한다. 구조 타입은 `RentalGeneration(bytes32 binding,uint256 firstNonce,bytes32 challenge,uint64 expiresAt)`이다. `binding`은 208바이트를 아래 순서와 길이로 연결한 뒤 Keccak-256한 값이다.

| 순서 | 값 | 길이 |
| --- | --- | --- |
| 1 | 대여 세대 | 8 |
| 2–3 | 지점 UUID, 기기 UUID | 각각 16 |
| 4–7 | 등록 다이제스트, 실행 측정, 배포 다이제스트, 체인 ID | 각각 32 |
| 8–9 | 정산 계약 주소, 대여 계정 주소 | 각각 20 |

보드는 새 키를 만들었지만 지급·한도 서명에서 쓸 수 없는 후보 상태를 유지해야 한다. 이 상태에서 얻은 첫 nonce·계정과 보드 실행 측정, 인증된 배포·등록, 보드 챌린지와 확정 시각을 후보 처리의 기대값으로 쓴다. 설정에 이미 등록된 운영자의 secp256k1 서명을 확인한다. 한 번 임의 발급한 챌린지는 이후 같은 승인 요청의 응답을 복구할 때만 사용한다. 현재 구현은 이 챌린지 및 후보 상태를 준비할 제품 작업과 분리되어 있다.

조건부 어댑터는 TF-M Protected Storage의 단일 UID에 전체 이미지를 저장하며, 보호 저장소 롤백 구성이 없는 빌드를 거절한다. 장치 자격 판정의 기본값은 비활성이다. 설정만으로 하드웨어 비휘발성 카운터·부트 롤백·생산 자격이 증명되지는 않는다. 읽기 오류, 다른 길이·플래그 및 불완전 응답으로는 빈 저널을 만들 수 없다. 부팅 경로는 별도 보호 활성화 기록으로 결속을 다시 검증하고 새 저널을 만들지 않아야 한다. [Arm 저장 원자성](https://arm-software.github.io/psa-api/storage/1.0/overview/architecture.html#atomicity-of-operations) [TF-M 보호 저장소 통합](https://trustedfirmware-m.readthedocs.io/en/tf-mv2.1.5/integration_guide/services/tfm_ps_integration_guide.html)

코어는 새 세대의 `nu54_device_init_rental_candidate`와 기존 초기화를 구분한다. 후보는 서명된 시간 앵커를 받을 수 있다. 저널 활성화가 빠졌거나 실패하면 지급·한도 프롬프트와 기존 nonce 사용을 거절하고, v1 초기화로 돌아가지 않는다. 결속은 대기 승인 없이 장치의 체인·계정·계약과 최초 nonce가 정확히 맞을 때만 완료한다. 기존 초기화는 저널을 붙일 수 없다.

보드 연결에서는 키를 만들기 전에 영속 신규 후보를 기록하고 그 마커를 기준으로 부팅해야 한다. 누락·손상된 신규 마커를 기존 등록으로 복구하면 안 된다. PS 저널을 활성화하는 동안 중단되면 기존 후보로 재시작하고 동일 증거만 재개한다. `pay_link.c`에서 BLE 메시지와 물리 입력을 직렬화하는 기존 work queue가 등록·동결과 프롬프트 무효화도 함께 처리해야 한다.

## 동결 대사 투영

RJP1은 277바이트 헤더와 실제 항목 수만큼의 126바이트 레코드를 사용한다. 헤더는 ASCII `RJP1` 4바이트, 208바이트 결속값, 시작 nonce 및 다음 nonce 각각 32바이트, 항목 수 1바이트 순이다. 각 행은 아래 순서다. 명시된 범위만 해시하고 빈 슬롯을 포함하지 않는다.

| 값 | 바이트 | 해석 |
| --- | --- | --- |
| 종류 | 1 | 지급 1, 한도 2 |
| 상태 | 1 | 발행 상태를 보호 저장소에 커밋함 1, 서명 응답 전 소각 2 |
| nonce | 32 | unsigned big-endian |
| 만료 | 8 | unsigned big-endian |
| 지급 가맹점 주소 | 20 | 한도에서는 0 |
| 지급 주문 ID | 32 | 한도에서는 0 |
| EIP-712 승인 다이제스트 | 32 | 예약된 승인 내용 |

발행 커밋은 응답이 네트워크에 전달됐음을 증명하지 않는다. 수집기는 가능한 체인 지급으로 대사한다. 소각은 원래 요청 종류를 남기되 지급·한도 건수와 별도 집계한다. 동결과 재부팅 복구는 미결 예약을 소각하거나 증거에 응답하지 않는다. 승인 원서명과 저장 전용 요청 해시는 투영에 없으며 보호 이미지를 전송하지 않는다. 보호 어댑터의 컴파일은 실제 구성의 `CONFIG_TFM_PS_MAX_ASSET_SIZE`가 1,814바이트 이상일 때만 가능하다. 순환 대여에는 인증된 보관과 차기 세대 시작 경계 또는 검증된 용량 증설이 필요하다.

## 등록 상태와 인증 동결

245바이트 RA01 보호 레코드는 신규 서명 비활성 키의 등록, 배포, 실행 측정, 최초 nonce와 준비/활성 상태를 기억한다. 등록 proof는 해당 준비 상태와 현재 실행 측정이 일치할 때만 저널을 열 수 있다. 저널 초기화가 끝난 뒤 활성 마커를 쓴다. 두 커밋 중 하나에서 응답이 유실되면 저장본을 다시 읽고 동일 후보만 계속한다. 준비 마커, 일부 읽기, 실행 측정 불일치, 활성 마커가 없는 고아 저널은 승인이나 legacy 복구 근거가 되지 않는다.

보드 부팅은 별도의 신규 설정 판별값 `RENTAL_JOURNAL_REQUIRED`에서만 보호 등록을 연다. 활성 기록, 보호 저널과 기존 계정/체인/계약의 일치가 확인되면 기존 키를 열 수 있다. 준비 기록은 앱이 활성 증거를 받기까지 서명 비활성이다. 기존 설정 형식은 이전대로 읽는다. 신형 판별값은 실험 기능을 붙이지 않은 빌드에서 거절한다. 보드의 준비 어댑터는 현장 설정 승인을 마치고 PIN을 기다리는 bonded setup에서만 동작한다. 새 키·체인·계약·운영자·최초 nonce·실측을 등록 proof와 대조한다. 실제 PIN 커밋은 신규 판별값을 저장하며 기존 nonce와 지급 키를 활성화하지 않는다. 보호 활성화 뒤에만 보드가 지급 키를 연다. 제품 발급 주체와 BLE 교환 및 검증된 부트 측정 공급은 계속 필요하다.

동결 요청 `rental.freeze.v2`는 기존 v1 정산 도메인의 독립 타입 `RentalFreezeRequestV2(bytes32 binding,bytes32 challenge,bytes32 channelNonce,uint64 expiresAt)`로 현재 대여 설정의 운영자 서명을 받는다. 먼저 `rental.freeze.challenge`를 호출한 등록 수집자에게만 보드가 최대 120초 동안 유효한 연결 nonce를 준다. 연결은 passkey를 검증한 LE Secure Connections L4 peer와 재사용하지 않는 연결 세대에 결속한다. 같은 peer의 새 nonce 발급 및 단절은 이전 nonce를 폐기한다. 다른 peer와 이전 nonce·기존 요청 타입은 같은 동결이나 행 조회를 인증하지 않는다. 등록 수집자 허가와 서명 issuer는 발급 시점의 세대·대상·챌린지를 재검증해야 한다. 보드의 실제 수집자 정책 공급자가 없으면 기본적으로 거절한다. 서버 챌린지 발급과 소비 기록은 수집자가 보관한다. 유효한 요청에서만 대기 승인을 취소하고 최초 동결 시각 및 저널 범위를 영속화한다. 동결 뒤에만 별도 등록 보드 인증키로 다음 구조의 영수증을 서명한다.

`RentalFreezeReceipt(bytes32 binding,bytes32 challenge,bytes32 projectionRoot,uint256 firstNonce,uint256 nextNonce,uint64 entryCount,uint64 frozenAt,uint64 expiresAt)`

보드 인증키는 대여 서명키 및 등록 운영자 키와 다르다. 실험 보드 어댑터는 자신의 기존 보드 인증키를 열며 새 키를 대신 만들지 않는다. 응답이 유실된 같은 챌린지는 최초 동결 시각과 같은 보호 범위에서 같은 서명만 낸다. 보드 인증 서명이 실패하면 이미 보존된 동결은 유지한다. RFR1은 향후 검증기 전달 형식의 253바이트 fixture이며, ASCII 표식 뒤 위 필드의 32바이트 값 5개, big-endian 8바이트 값 3개, 65바이트 ECDSA 순이다. 실제 BLE의 `rental.freeze.result`는 별도의 보드 인증 서명과 구조화한 필드를 반환한다. `rental.freeze.v2`의 `projectionIndex`는 같은 활성 수집 연결과 서명을 다시 검증해 이미 동결된 RJP1 행만 반환하며, 해당 행에는 어떤 서명도 없다. P01과 P07은 같은 [RJP1](../../packages/protocol/v2/testdata/rjp1.vectors) 및 [RFR1](../../packages/protocol/v2/testdata/rfr1.vectors) 벡터를 사용한다. P01과 P05 발급기는 [RFQ2](../../packages/protocol/v2/testdata/rfq2.vectors) 요청 digest 벡터를 공유한다.
