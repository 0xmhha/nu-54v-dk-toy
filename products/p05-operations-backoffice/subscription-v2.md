# 16 구독 회차와 사용자 승인

P05는 불변 약관 버전과 SHA-256, 동의 시각, 지점, 고객 참조, 자산 단위, 주기 및 다음 납기를 저장한다. 약관이 바뀌면 새 버전에 다시 동의한다. 가입과 해지는 지점에 등록된 고객 mTLS 인증을 사용한다. P02에 자동 인출 권한이 생기지 않는다.

회차 스케줄과 해지는 같은 구독 행을 먼저 잠근다. 다음 회차를 만들 때 구독·예정 시각이 다른 독립 청구가 없음을 제약으로 보장한다. 한 회차는 한 주문으로 귀속된다. 스케줄러는 예정된 청구와 업무 주문만 만든다. 고객이 미결 목록 또는 알림에서 그 주문을 열면 공통 클레임, 서명 견적, 보드 확인, 제출 및 P07 확정 대사 경로를 사용한다.

해지가 먼저 확정되면 이후 회차를 만들지 않는다. 이미 만든 주문의 견적이 미발급이면 판매를 닫는다. 견적 발급과 해지의 경쟁은 판매 행에 직렬화한다. 이미 발급 또는 제출한 견적은 원래 주문에서 포함·만료와 늦은 최종성을 계속 확인한다. 해지는 기존 영수증, 지급 상태 또는 장부 사실을 취소하지 않는다.

P02는 회차 참조와 로컬 알림 선택을 저장한다. 중복 알림, 여러 폰과 앱 재시작에서 같은 회차를 조회한다. 알림 권한이 없거나 후에 철회해도 미결 목록에서 같은 회차에 접근할 수 있다. 알림 링크는 로그인과 회차의 소유자 확인을 거쳐야 한다.

## 수용 시험

- 서로 다른 두 인증서가 같은 고객의 같은 회차를 요청할 때 한 업무 주문, 한 견적, 한 계정 승인만 정산한다.
- 소유권이 다른 고객에게는 회차·영수증·결제 정보가 반환되지 않는다. 계약 금액과 자산을 앱이 변경할 수 없다.
- 취소와 발행의 두 순서를 실 DB에서 시험한다. 발행 없는 취소의 미래 회차는 0건이며 발행한 견적은 늦은 대사를 유지한다.
- 알림을 허용한 경우와 거절한 경우 모두 미결 목록이 정상이다. 두 알림의 재실행과 새 앱 세션은 동일한 주문으로 복귀한다.

새 약관과 금액의 동의는 새 버전의 식별자와 원문 해시에 묶는다. 기존 구독을 교체할 때 한 커밋에서 기존 미래 회차를 중지하고 새 구독을 만든다. 기존에 발급한 회차는 원 지급 조건을 유지한다. 일시 정지는 새 회차 발행을 중지하고 발급된 회차를 보존한다. 재개는 건너뛴 회차를 소급 발행하지 않으며 명시적으로 다음 납기를 표시한다.

알림 권한은 사용자가 신청했을 때만 운영체제를 통해 요청한다. 거부 시 대응 상태를 기기에 보존하고 미결 목록 접근은 계속 제공한다. 전화기에는 서명이나 수납 권한이 없는 회차 참조만 예약한다.

격리 PostgreSQL과 Anvil의 정상 통합 경로는 `make commercial-integration-test`의 `TestLoopbackSettlementEvidenceAndRefund`에서 확인한다. 별도 인증서를 가진 두 전화기가 하나의 회차와 원금에 합류한다. 보드가 승인한 한 건이 만료 전에 체인에 포함된 뒤 이용자가 새 가격에 동의하고 미래 회차를 해지한다. 그 뒤 체인 확정 시점에 단일 지급과 단일 전표를 저장하며 두 전화기에서 기존 지급 회차를 확인할 수 있다.

앱은 사용자가 구독 관리를 열거나 갱신할 때 현재 미결 목록을 기기 알림과 맞춘다. 알림 권한 또는 기기 설정 저장소에 접근할 수 없는 경우에도 미결 목록에서 동일한 회차를 결제할 수 있다. Android와 iOS 네이티브 모듈을 각각 컴파일했고 권한 거부·기기 설정 읽기 오류는 앱 화면 시험으로 확인했다. Android API 34 에뮬레이터에서 권한 거부와 실제 재부팅 뒤 앱 화면을 열지 않은 상태의 예약 알림 도착을 확인했다. 알림에는 일반 안내 제목만 있으며 잠금 화면 표시가 금지된다. iOS Simulator Release 빌드와 외부 링크의 시스템 열기 안내를 확인했다. iOS 현장 기기의 로컬 알림 도착과 탭 동작은 후속 인수 대상이다.

### 예약 알림 및 회차 수신

P02는 서버에서 조회한 다음 활성 회차를 기기 알림으로 예약한다. 잠금 화면 미리보기에는 청구 금액, 상점, 고객, 주문, 키가 들어가지 않는다. 알림의 로컬 식별자는 기존 회차나 구독을 찾는 데만 쓰며, 활성 mTLS 주체로 같은 미결 목록을 다시 조회한 뒤에만 일치하는 주문을 연다. 다른 기기의 해지나 가격 변경을 아직 받은 적이 없을 때에는 이전 예약의 일반 알림이 나타날 수 있다. 이 경우 최신 서버 조회가 주문 접근과 발급 여부를 결정한다. 예약은 금액 승인, 지급 제출, 신규 회차 생성 권한을 갖지 않는다.

Android는 앱 전용 저장소에 로컬 알림 시각과 종료 시각을 보관하고 정상 재부팅 후 유효한 예약만 다시 등록한다. iOS는 운영체제의 로컬 알림에 같은 예약을 맡긴다. 플랫폼의 알림 거부 및 강제 중지 상태에서는 기존 결제 탭에서 미결 회차에 접근한다.

### 상품 조건과 건너뛰기

022 이전 상품과 회차는 기존의 현장 수령 조건을 유지한다. 이후 새 약관은 `physical` 또는 `digital`을 명시하며, 활성 여부 외의 기존 약관 변경에는 새 버전이 필요하다. 회차 발급 시 당시 상품 조건을 고정한다. 현장 수령은 기존 픽업·조리 경로를 사용한다. 디지털 이용권은 동일한 확정 지급 커밋에서 회차당 하나의 사적 영수증과 권리를 발행한다. 전체 환불이 확정되면 이용권을 종료한다. 부분 환불은 잔존 원금과 이용권을 유지한다.

고객이 미발급 회차를 건너뛰면 해당 견적의 새 발급을 닫으며 다른 기기의 재시도도 같은 청구서를 반환한다. 이미 서명된 견적은 원래 만료 범위에서 대사한다. 해지 후 다시 구독하거나 새 약관으로 등록해도 같은 구독 계열의 이미 발행한 회차를 다시 만들지 않는다.

### 회차 납기·견적 기한·미지급 확정

P05는 고객과 지점을 확인한 뒤 원 청구서 납기와 서명 견적의 체인 기한을 각각 보여 준다. 서명 견적의 기한이 지나면 회차는 대사 중으로 표시되며 같은 회차의 상태만 조회한다. 이미 기한 내 포함된 지급은 늦게 확정돼도 원래 영수증을 연다. P05가 P07의 연속 확정 범위와 미소비 증거를 검증해 `sale_resolution`을 기록한 경우에 견적 만료를 표시한다. 미서명 회차의 건너뛰기와 일반 종료 표시는 견적 만료와 구분한다. 045는 조회용 뷰와 권한 제한 함수만 추가한다. 기존 응답의 `state`는 유지하며 목록의 선택적 `stage`와 상세의 선택적 `subscription`을 추가한다. ### 기기 인수 시험

- Android API 34의 격리 에뮬레이터에서 앱의 실제 알림 예약을 실행한 뒤 재부팅했다. 앱 화면을 열기 전에 제목만 있는 알림 한 건을 받았고, 잠금 화면 비공개 플래그와 알림 권한 거부 시 예약 거절을 확인했다.
- iOS 27의 앱 호스트 XCTest가 실제 네이티브 모듈을 호출해 권한 허용 뒤 로컬 대기 알림 한 건을 등록했다. 일반 제목, 비어 있는 본문과 사용자 정보, 취소 뒤 대기 건수 0을 확인했다. 별도 XCUITest는 전달된 로컬 알림을 눌러 등록되지 않은 고객의 접근 제한을 확인했다.
- 로컬 opsd와 결합하는 인수는 `NU54_SUBSCRIPTION_NATIVE_LAB`에 지정한 새 디렉터리의 `public-keys.json`에 시험 기기의 네이티브 P-256 공개키를 넣고 `make commercial-integration-test`를 실행한다. 같은 디렉터리를 `scripts/ios/scene-smoke/run-subscription-enrolled.sh`에 전달한다. 앱은 발급된 시험 인증서를 기존 네이티브 등록 경로에 적용하며, 실제 mTLS로 현재 회차를 조회한다. 파일은 시험 인증서와 합성 참조만 담는다. 키는 기기에서 생성되어 이동하지 않는다.
- iOS 등록 시험은 직접 발급한 클라이언트 인증서와 중간 인증서 한 장을 포함한 체인을 시험한다. 두 앱이 공유하는 네이티브 C3 모듈은 중간 인증서가 없는 경우 Foundation에 빈 배열 대신 `nil`을 전달한다. [Apple NSURLCredential 문서](https://developer.apple.com/documentation/foundation/nsurlcredential/init%28identity%3Acertificates%3Apersistence%3A%29)

2026-11-20 iOS 27 시험에서 네이티브 기기 키에 발급한 직접 서명 인증서로 실제 opsd의 미결 회차를 조회했다. 로컬 알림을 탭한 뒤 W18에서 올바른 회차 한 건을 골랐고 W19에서 동일한 원주문 ID, 미지급 상태와 별도의 보드 결제 검토 버튼을 확인했다. 이 시험에서 결제 버튼은 누르지 않았다. 가입자 전환 도중 이전 권한 확인이나 예약 결과가 늦게 도착해도 새 가입자의 알림 목록과 저장 기록을 덮어쓰지 않는 두 회귀를 추가했다.

W09의 ‘내 결제’는 보드 페어링이나 OS 알림 동의 없이 열 수 있다. W18의 미결 목록은 등록된 C3 주체로 조회하며, 회차 선택은 원주문 상태를 조회한다. 두 설치와 재시작에서도 같은 회차·판매 ID를 유지한다. 검토 화면에 들어가기 전에는 지급자 클레임·견적·보드 서명·전송이 생기지 않는다.

권한 거부 인수는 격리 iOS Simulator에서 `scripts/ios/scene-smoke/run-subscription-denied.sh SIMULATOR P02_DERIVED_DATA FIXTURE RESULTS`로 실행한다. 두 QA 앱 설치는 각각 다른 네이티브 공개키를 발행한다. 실행마다 새 QA 번들 두 개를 서명하므로 전용 시뮬레이터에서 OS 권한 창을 각각 검증한다. 두 앱은 실제 고객 등록 화면에서 별도 키를 발행하고, 등록서와 따로 제공되는 TLS·주문 제시 지문을 대조한다. 루프백 등록 준비 서비스는 실행 한정 승인과 두 역할의 한 번짜리 응답만 허용한다. 시험은 성공·실패·처리 가능한 종료 신호에서 임시 등록 및 XCTest 자료를 정리하고 해당 QA 앱만 제거한다. 일회 등록 권한은 시험 서비스를 종료하면서 폐기하며, 새 번들은 이전 등록을 사용하지 않는다. 결과는 단계별 통과 상태와 건수만 남긴다. `FIXTURE/public-keys.json`이 생기면 같은 디렉터리를 `NU54_SUBSCRIPTION_NATIVE_LAB`에 지정해 정산 통합 시험을 실행한다. 각 앱에서 OS 알림을 거부한 뒤 홈의 ‘내 결제’로 시작해 같은 미결 판매를 연다. 앱을 다시 시작해 같은 경로를 한 번 더 확인한다. 두 설치 모두 통과하면 정산 시험이 `read-only.json`에 판매 상태와 클레임·견적·제출·지급 건수를 기록한다. 이후 별도 보드 승인 시험이 해지와 늦은 확정 대사를 진행한다. 정산 시험에는 UTF-8로 만든 격리 PostgreSQL에 P05/P07 마이그레이션을 적용한 뒤 `P05_SETTLEMENT_TEST_DATABASE_URL`을 지정하고 `sh products/p05-operations-backoffice/test/settlement/anvil.sh`를 실행한다.

현재 iOS 합성 인수에서는 일반 고객 등록 2회, 실제 시스템 알림 거절 2회,
같은 미결 회차 조회와 앱 재시작 2회가 통과했다. 조회 직후 원장에는
클레임·견적·제출·지급이 각각 0건이었다. 이후 별도 보드 승인 건만 지급 1건으로
확정되었으며 재동의·해지 후 도착한 확정도 반영됐다.

두 터미널에서 같은 사유 임시 디렉터리를 지정한다. 첫 터미널은 고유한
QA 앱을 설치하고 일반 **내 결제** 화면에서 앱마다 공개키를 발행한다.
시험 발급자가 준비한 등록서와 별도로 제공하는 두 지문을 입력하고 시스템
알림 권한을 거절한다. 각 앱은 수동으로 **구독 관리**에서 같은 회차를 열고
앱 재시작 후 같은 미결 주문을 다시 연다.

```sh
# Terminal 1
FIXTURE=$(mktemp -d)
chmod 700 "$FIXTURE"
bash scripts/ios/scene-smoke/run-subscription-denied.sh "$SIM" "$DERIVED" "$FIXTURE" "$RESULT"

# Terminal 2. Use the same FIXTURE path and a disposable migrated UTF-8 database.
test -s "$FIXTURE/public-keys.json"
NU54_SUBSCRIPTION_NATIVE_LAB="$FIXTURE" \
  P05_SETTLEMENT_TEST_DATABASE_URL="$ISOLATED_DSN" \
  sh products/p05-operations-backoffice/test/settlement/anvil.sh
```

인수 결과에는 `RESULT/test-summary.json`의 OS 거절·등록·조회·재시작 건수와
`FIXTURE/read-only.json`의 개인 식별자가 없는 집계만 보관한다. 임시 앱과 등록
자료는 실행 종료 시 정리한다.

Android 시험은 새 API 33 이상 에뮬레이터와 독립 앱 ID로 서명한 일반 P02 APK를 사용한다. APK를 설치하고 테스트용 클립보드 앱을 일회 서명한다. 이 앱은 에뮬레이터의 정상 등록 폼에 합성 등록서와 지문을 붙여넣는 데 사용한다.

FIXTURE=$(mktemp -d)
bash scripts/android/subscription-smoke/build-clipboard.sh "$ANDROID_BUILD_TOOLS" "$FIXTURE/clipboard.apk"
python3 scripts/android/subscription-smoke/run.py "$ANDROID_SERIAL" "$PACKAGE" "$FIXTURE/clipboard.apk" "$FIXTURE" --mode lifecycle

W19 모드는 같은 청구서의 미결 조회, OS 알림 거절, 재시작, 포함 대기, 확정 디지털 영수증, 별도 미승인 회차 건너뛰기, 서명 견적의 대사와 확정 만료를 차례로 확인한다. 각 장면 전에 합성 서버가 원장과 체인 상태를 확인하며, 검증을 마치면 `lifecycle-report.json`에 건수와 통과 여부를 기록한다. W18 약관·일시정지·재개·재동의·해지는 양쪽 실행에서 모드를 `terms`로 바꿔 실행한다.

혼합 iOS·Android는 `run.py`의 기본 `preview` 모드와 `NU54_SUBSCRIPTION_PAIR_ANDROID=1`을 지정한 iOS 거절 시험을 각각 다른 새 디렉터리에서 실행한다. `python3 scripts/android/subscription-smoke/pair.py "$FIXTURE" "$ANDROID_FIXTURE" "$IOS_FIXTURE"`가 독립 공개키를 모으면 그 `FIXTURE`로 정산 시험을 시작한다. 이때 `NU54_SUBSCRIPTION_NATIVE_FLOW`는 지정하지 않는다. 혼합 확인은 두 앱이 같은 고객의 같은 원 회차를 재시작 전후 읽었으며 조회 자체의 클레임·견적·제출·지급이 각각 0건임을 시험한다.
