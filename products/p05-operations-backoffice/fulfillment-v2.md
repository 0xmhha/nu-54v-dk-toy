# Fulfillment delivery and device effects

P05 prepares each immutable event under the active P07 stream epoch and an exclusive, expiring outbox lease. The epoch changes on a read generation switch or a newly recorded finalized incident, including one that was subsequently resolved. The authorization is persisted with the exact event digest and lease fence. It expires with the lease.

The dispatcher releases its DB transactions before performing HTTPS. The receiving service authenticates the issuing mTLS identity and branch, resolves the event against the persisted authorization, checks the same epoch and commits the unique inbox receipt in a short transaction coordinated with the stream incident lock. The durable inbox acceptance is the fulfillment authorization point. An incident which acquires the stream lock first prevents a new acceptance. A receipt committed ahead of the incident is an authoritative historical fact. It does not authorize replay or a new device effect. The receiver returns the same receipt for the same event and digest and refuses an identity collision.

After HTTPS, P05 checks the live epoch again while committing any acknowledgement. An epoch change or superseded lease leaves the attempt unresolved. Recovery uses the same event key and digest in a new lookup. Only a scoped exact absence permits a fresh attempt. A response of unknown keeps the hold. Third-party latency holds neither the P07 incident fence nor a P05 transaction.

A printer handoff records the durable attempt before sending. Loss of the response leaves that attempt unknown and stops automatic sends. An authorized branch employee can confirm observed paper under that attempt or explicitly authorize one identified reprint of the same receipt. A reprint is a new device attempt with an audited operator decision and cannot cause a second sale, pickup, or journal entry. A physical result is authoritative only when acknowledged by the enrolled device or confirmed by the branch employee.

## Enrollment and local verification

In opsd, enroll the acknowledging consumer database login with `P05_RECEIVER_DATABASE_URL` and a JSON settings file via `P05_RECEIVER_GRANTS`. Each certificate SHA-256 fingerprint maps to `branches` and `expiresAt`. The sender includes the persisted epoch and attempt fence in `X-NU54-Delivery-Epoch` and `X-NU54-Delivery-Fence`. The receiver reconstructs the canonical event from the immutable journal projection and compares its digest before accepting or reporting absence.

Use distinct logins for `P05_PRINT_DATABASE_URL` and `P05_PRINT_STAFF_DATABASE_URL`. `P05_PRINT_STAFF_GRANTS` maps an enrolled mTLS fingerprint to an expiring `printer_staff` principal and the database grant scopes the employee to a branch. The private endpoint `GET /v2/fulfillment/print-attempts?branchId=…&receiptRef=…` returns current attempt references and outcomes. The employee uses `POST /v2/fulfillment/print-decisions` with `branchId`, `attemptId`, `idempotencyKey` and action `confirm_printed` or `reprint`. The worker runs the executable at `P05_PRINT_DEVICE` pinned by `P05_PRINT_DEVICE_SHA256`, sends one JSON line with attempt, receipt, branch and pickup, and accepts only a matching `printed` response. The fixture uses synthetic devices. It cannot establish that paper emerged from a physical printer.

The relay uses the same short epoch fence to admit the already persisted transaction hash under an exclusive worker lease. Admission sets its result unknown before releasing DB locks and submitting those same signed bytes to the RPC. An incident blocks new admissions. A send admitted before an incident may already have reached the network and cannot be canceled. While held, recovery can query the exact known receipt/hash. An acknowledgement arriving after the epoch changes cannot resolve the attempt. The worker reconfirms immutable observations once the active view is available.
